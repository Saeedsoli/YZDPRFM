## بخش ۲ — یافته‌های جدید این ممیزی 🆕

### 🔴 ۱. دستکاری قیمت — آسیب‌پذیری مالی
تست واقعی انجام شد:
```bash
POST /api/orders  {"items":[{"name":"اونتوس","price_toman":1}]}
→ HTTP 201 "سفارش با موفقیت ثبت شد"
```
**سرور قیمت را از کاربر می‌پذیرد و با دیتابیس تطبیق نمی‌دهد.**
هر کسی می‌تواند عطر ۴,۷۰۰,۰۰۰ تومانی را ۱ تومان بخرد.
*(سفارش تستی پاک شد)*

### 🔴 ۲. حذف مقاله بدون احراز هویت
```bash
DELETE /api/articles/ART-1001   (بدون هیچ توکنی)
→ HTTP 200 "مقاله با موفقیت حذف گردید"
```
همه Endpointهای نوشتاری باز هستند: حذف مقاله، ویرایش، تغییر تنظیمات، خواندن تمام سفارشات مشتریان.
*(مقاله بازیابی شد)*

### 🔴 ۳. Dockerfile شکسته — استقرار Fail می‌شود
```dockerfile
COPY server.js ./                      # ❌ الان در src/ است
COPY perfumes_catalogue_seed.json ./   # ❌ الان در data/ است
COPY images ./images                   # ❌ الان در public/images است
```
بعد از سازماندهی گیت‌هاب، Dockerfile به‌روز نشد. **بیلد روی Liara می‌شکند.**

### 🔴 ۴. دو نسخه متفاوت از فایل‌های حیاتی
| فایل | وضعیت |
|---|---|
| `server.js` ↔ `src/server.js` | ⚠️ **محتوای متفاوت** |
| `app_preview.html` ↔ `public/app_preview.html` | ⚠️ **محتوای متفاوت** |

کدام اصل است؟ ریسک بالای ویرایش فایل اشتباه.

### 🟠 ۵. آلودگی کامل داده: «(Inspired by)» در ۱۰۰٪ رکوردها
```
name_en = "Aventus (Inspired by Creed)"   ← هر ۲,۱۰۶ رکورد
```
در UI پاکسازی شد، اما **در خود دیتابیس باقی است**. هر جای جدیدی که از `name_en` بخواند، دوباره ظاهر می‌شود. تو صریحاً به این اعتراض کردی.

### 🟠 ۶. داده‌های ساختگی در فیلدهای واقعی
```
perfumer: "House Master Perfumer" × 2064   ← عطرساز واقعی نیست
release_year: 2010 × 258, 2011 × 258       ← توزیع مصنوعی
```
اگر این‌ها در PDP نمایش داده شوند، اطلاعات نادرست به مشتری می‌دهیم. یا حذف شوند یا با داده واقعی جایگزین.

### 🟠 ۷. تکرار گسترده فایل‌ها
- **۳۲ سند** در ریشه + **۳۲ سند** در `docs/` (دوبل)
- **۱۱ اسکریپت** در ریشه + **۷** در `scripts/`
- ۴ فایل JSON دیتابیس در ریشه + `data/`
- `data/` در `.gitignore` **نیست** → ۹.۳MB دیتا به گیت می‌رود (این عمداً درست است، اما `quiz_db.json` و `quiz_compact.json` تکراری‌اند)

## بخش ۴ — نقاط کور (هرگز مطرح نشد)

**هویت:** ثبت‌نام، ورود با OTP پیامکی، «سفارشات من»، آدرس‌های ذخیره‌شده
**تسویه:** فرم آدرس، انتخاب استان/شهر ایران، کد پستی، خلاصه سفارش
**انبار:** فیلد `stock` هست ولی هرگز کم نمی‌شود → فروش بیش از موجودی
**پس از خرید:** پیامک تأیید، کد رهگیری پستی، تغییر وضعیت سفارش
**قانونی ایران:** نماد اعتماد الکترونیکی (بدون آن درگاه پرداخت نمی‌دهند)، قوانین، حریم خصوصی، تماس
**عملیات:** کد تخفیف، فاکتور رسمی (مالیات عمداً پیاده نشد — قیمت اعلام‌شده همان قیمت پرداختی است)
**فنی:** دیتابیس واقعی (JSON در برابر همزمانی شکننده است)، rate limiting، بکاپ، لاگ خطا، صفحه ۴۰۴ فارسی، حالت Loading
