# مشخصات فنی اتصال به درگاه‌های پرداخت آنلاین (Payment Integration Spec)
**پروژه:** فروشگاه آنلاین عطر یزد | Yazd Perfume  

این سند معماری فنی اتصال به درگاه مستقیم بانک‌های عضو شبکه **شاپرک** (مانند سامان / پارسیان / ملت) به همراه درگاه واسط **زرین‌پال** به عنوان درگاه جایگزین (Fallback Mechanism) را مشخص می‌کند.

---

## ۱. جریان پردازش تراکنش و معماری (Payment Flow Architecture)

```
[مشتری در Checkout] ──> [انتخاب درگاه (شاپرک / زرین‌پال)] ──> [ثبت سفارش اولیه در حالت PENDING]
                                                                        │
                                                                        ▼
[دریافت Token/Authority از API درگاه] <─── [درخواست ایجاد تراکنش با مبلغ نهایی]
            │
            ▼
[هدایت امن کاربر به IPG درگاه بانک]
            │
            ▼ (انجام عملیات توسط کاربر در بانک)
            │
[بازگشت به Callback URL فروشگاه: /api/payment/verify]
            │
            ▼
[بررسی توکن تکراری + فراخوانی متد Verify درگاه از بکن‌د]
            │
            ├─► در صورت موفقیت (Status OK & Verify Success):
            │   ├── ۱. تغییر وضعیت سفارش به PAID
            │   ├── ۲. کسر خودکار موجودی کالاها
            │   ├── ۳. ارسال پیامک تایید سفارش با کد پیگیری
            │   └─► نمایش صفحه موفقیت سفارش (/checkout/success)
            │
            └─► در صورت شکست یا انصراف:
                ├── ۱. تغییر وضعیت سفارش به PAYMENT_FAILED
                └─► نمایش صفحه خطای پرداخت با دکمه "تلاش مجدد" (/checkout/failed)
```

---

## ۲. مکانیزم جلوگیری از پرداخت تکراری و نفوذ (Idempotency & Anti-Double-Spend)

1. **کلید یکتایی تراکنش (Idempotency Key):**
   - به ازای هر سفارش، یک `Merchant_Transaction_ID` یکتا ترکیبی از کد سفارش و Timestamp تولید می‌شود (مثال: `YZD-10842-1721389200`).
   - سیستم دیتابیس بکن‌د مجاز نیست برای یک سفارش مشخص، دو تراکنش همزمان در حالت `PENDING` ایجاد کند.
2. **بررسی صحت مبلغ (Amount Cross-Check):**
   - هنگام دریافت Callback، مبلغ بازگشتی از درگاه مستقیماً با مبلغ فاکتور صادر شده درون دیتابیس چک می‌شود. در صورت عدم تطابق دقیق، تراکنش ریجکت شده و به حالت `AMOUNT_MISMATCH` می‌رود.
3. **اعتبارسنجی یکباره Callback (Single-Use Callback Execution):**
   - بلافاصله با فراخوانی اولیه آدرس Verify، وضعیت تراکنش از `PENDING` به `VERIFYING` تغییر می‌کند تا از ارسال همزمان چند درخواست تکراری (Replay Attack) جلوگیری شود.

## ۳. مشخصات متدهای API پرداخت (Payment API Methods)

### ۳.۱. درخواست ایجاد توکن پرداخت (`/api/payment/request`)
- **ورودی (Payload):**
  ```json
  {
    "order_id": "YZD-10842",
    "gateway_provider": "SHAPARAK_SAMAN",
    "amount_toman": 1450000,
    "callback_url": "https://yazdperfume.ir/api/payment/verify"
  }
  ```
- **خروجی (Response):**
  ```json
  {
    "status": "SUCCESS",
    "payment_url": "https://sep.shaparak.ir/OnlinePG/OnlinePG",
    "token": "A849201948102948102"
  }
  ```

### ۳.۲. بررسی و تایید نهایی تراکنش (`/api/payment/verify`)
- **روش اجرا:** فراخوانی Server-to-Server مجزا پس از دریافت Redirect از مرورگر کاربر.
- **تایم‌آوت درخواست (Request Timeout):** ۱۵ ثانیه. اگر درگاه بانکی در این مدت پاسخ ندهد، وضعیت تراکنش در حالت `NEEDS_MANUAL_VERIFY` قرار گرفته و تا ۳ بار با فواصل زمانی ۵ دقیقه‌ای توسط Worker پس‌زمینه استعلام می‌شود.

---

## ۴. مکانیزم سوئیچینگ اتوماتیک به درگاه پشتیبان (Automated Fallback)

اگر درگاه اصلی شاپرک ظرف مدت ۳ دقیقه ۳ بار خطای ارتباطی (Network Timeout یا HTTP 5xx) صادر کند:
1. سیستم به صورت اتوماتیک درگاه پیش‌فرض UI را روی **زرین‌پال** سوئیچ می‌کند.
2. یک هشدار متنی در پنل ادمین ثبت شده و SMS اطلاع‌رسانی اختلال درگاه به مدیر فنی ارسال می‌شود.
