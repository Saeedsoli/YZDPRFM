# مرجع API — عطر یزد

مسیرهای ثابت و پارامتری در سه سطح دسترسی. پاسخ‌های API عموماً
JSON با `charset=utf-8` هستند؛ فایل‌های دانلود و جریان‌ها استثنا دارند.

> **این سند زنده است.** `node scripts/audit_docs.js` بررسی می‌کند
> هر مسیر موجود در کد اینجا مستند شده باشد — و برعکس، مسیری که
> اینجا هست ولی در کد نیست گزارش می‌شود.

---

## احراز هویت

| سطح | روش | مدت |
|---|---|---|
| عمومی | ندارد | — |
| مشتری | هدر `X-Customer-Token` یا کوکی `yazd_customer` | ۳۰ روز |
| مدیر | هدر `Authorization: Bearer` یا کوکی `yazd_admin` | ۸ ساعت |

نشست‌ها در جدول `sessions` ذخیره می‌شوند و با ری‌استارت سرور
از بین نمی‌روند.

---

## کدهای پاسخ

| کد | معنی |
|---|---|
| `200` `201` | موفق |
| `400` | ورودی نامعتبر (در لاگ ثبت نمی‌شود) |
| `401` | نیازمند ورود |
| `403` | دسترسی به منبع دیگری |
| `404` | یافت نشد |
| `409` | تکراری |
| `429` | عبور از محدودیت نرخ |
| `500` | خطای سرور (در لاگ ثبت می‌شود) |

قالب خطا:
```json
{ "error": "پیام فارسی قابل نمایش به کاربر" }
```

# محصولات

### `GET /api/products`

| پارامتر | پیش‌فرض | توضیح |
|---|---|---|
| `q` | — | جستجو (تا ۵ واژه، یکسان‌سازی فارسی) |
| `family` | — | `woody` `floral` `citrus` … |
| `gender` | — | `MEN` `WOMEN` `UNISEX` |
| `brand` | — | نام فارسی یا لاتین |
| `page` | ۱ | شماره صفحه |
| `limit` | ۲۴ | حداکثر ۶۰ |
| `sort` | — | `price_asc` `price_desc` `name` `brand`؛ برای فهرست سمپل `sample_price_asc` |
| `sample_5` | `0` | `1` = فقط محصولات دارای سمپل ۵ میل با قیمت معتبر و قابل سفارش؛ پاسخ دارای `sample_price` است |
| `full` | `0` | `1` = شامل متغیرهای قابل نمایش |

بدون `full=1` پاسخ سبک است (کارت محصول به متغیرها نیاز ندارد) —
۱۲ کیلوبایت به‌جای ۸۰.

```json
{
  "total": 2111, "page": 1, "limit": 24, "totalPages": 88,
  "products": [{
    "id": "YZD-PROD-0029", "slug": "creed-aventus",
    "name_fa": "اونتوس", "name_en": "CREED - Aventus",
    "brand_fa": "کرِید", "gender": "MEN",
    "family_fa": "مدیترانه‌ای میوه‌ای",
    "notes": { "top": ["آناناس", "ترنج", "سیب"] },
    "image_url": "/images/products/brand-creed.jpg",
    "min_price": 196000, "in_stock": true, "variant_count": 7
  }]
}
```

**جستجو:** `کرید` = `کرِید` = `كريد` → هر سه یک نتیجه.
اعراب حذف و حروف عربی یکسان می‌شوند.

**مرتب‌سازی:** مقدار `sort` از یک **فهرست سفید** رد می‌شود و هرگز
مستقیم وارد SQL نمی‌گردد. مقدار ناشناخته → ترتیب پیش‌فرض.
قیمت در جدول `products` نیست، پس `price_asc` / `price_desc` روی
`MIN(price_toman)` متغیرها زیرپرس‌وجو می‌زنند.

### `GET /api/products/:slug`

محصول کامل با همه متغیرها.

### `GET /api/brands` · `GET /api/families`

فهرست با تعداد محصول هر گروه.

# کوییز

### `POST /api/quiz`

```json
{ "answers": {
  "gender": "MEN", "temperature": "گرم",
  "season": "پاییز و زمستان", "occasion": "رسمی",
  "family": "شرقی", "budget": "mid"
}}
```

هر پاسخ می‌تواند `ANY` باشد. امتیازدهی وزنی: جنسیت و خانواده ۳،
فصل و مناسبت و طبع ۲. حداکثر ۲ محصول از هر برند.

منطق امتیازدهی در `src/taste.js` است تا `/api/taste/suggest` هم از
همان فرمول استفاده کند.

**پاسخ:**
```json
{ "total": 6, "results": [...], "total_products": 2111,
  "profile": { "gender": "MEN", "family": "شرقی" },
  "profile_saved": true, "budget_relaxed": false }
```

اگر کاربر وارد شده باشد، پاسخ‌ها به‌عنوان پروفایل بویایی در جدول
`customers` ذخیره می‌شوند (`profile_saved`). برای مهمان، مرورگر
خودش در `localStorage` نگه می‌دارد.

### `GET /api/notes`

فهرست نُت‌های بویایی با شمار محصول — برای نوار فیلتر.

| پارامتر | پیش‌فرض | کار |
|---|---|---|
| `position` | همه | `top` · `middle` · `base` · `accord` |
| `min` | ۱۲ | حداقل شمار محصول برای نمایش |
| `limit` | ۶۰ | سقف تعداد |

```json
{ "notes": [ { "note_key": "وانیل", "note": "وانیل", "count": 916 } ],
  "position": null }
```

`min` جلوی شلوغی را می‌گیرد: نُتی که یک عطر دارد در فهرست فیلتر
مزاحم است، نه مفید. **شمار اعلام‌شده تضمین می‌شود** — چیپی که
می‌گوید ۹۱۶، دقیقاً ۹۱۶ نتیجه می‌دهد و هرگز بن‌بست نیست.

### فیلتر نُت در `/api/products`

```
/api/products?note=وانیل
/api/products?note=وانیل,ترنج        ← هر دو (AND)
/api/products?note=وانیل&gender=WOMEN
```

چند نُت با **AND** ترکیب می‌شوند نه OR: «وانیل و ترنج» یعنی
محصولی که هر دو را دارد. سقف چهار نُت. تطبیق دقیق است، پس نام نُت
باید همان چیزی باشد که `/api/notes` می‌دهد.

# پروفایل بویایی

### `POST /api/taste/suggest`

پیشنهاد بر پایه پروفایل. دو راه ورودی:

- **کاربر واردشده** — پروفایل از دیتابیس خوانده می‌شود (`source: account`)
- **مهمان** — پروفایل در بدنه درخواست می‌آید (`source: guest`)

```json
{ "answers": { "gender": "WOMEN", "family": "گلی" } }
```

```json
{ "items": [...], "profile": {...},
  "summary": ["زنانه", "گلی"],
  "budget_relaxed": false, "source": "guest" }
```

`budget_relaxed` یعنی در محدوده بودجه گزینه کافی نبود و بازه بازتر
شد — رابط این را صادقانه به کاربر می‌گوید.

پروفایل با کمتر از دو معیار «بی‌معنا» شمرده می‌شود و پیشنهادی
تولید نمی‌کند.

### `GET /api/taste/profile`

پروفایل ذخیره‌شده کاربر واردشده.

```json
{ "authenticated": true, "profile": {...},
  "summary": ["زنانه", "گلی"], "updated_at": "2026-08-01 12:00:00" }
```

### `DELETE /api/taste/profile`

حذف پروفایل — کاربر باید بتواند فراموش شود. نیازمند ورود (۴۰۱).

# سبد و سفارش

### `POST /api/cart/sync`

وضعیت زنده چند SKU — برای همگام‌سازی سبدی که در `localStorage`
مرورگر مانده است.

```json
{ "skus": ["YZD-0029-EDP-050"] }
```

```json
{
  "variants": [{
    "sku": "YZD-0029-EDP-050",
    "price": 4700000, "stock": 12,
    "state": "IN_STOCK", "max_quantity": 12,
    "slug": "creed-aventus",
    "image_url": "/images/products/brand-creed.jpg",
    "name": "کرِید — اونتوس — ادو پرفیوم دست‌ساز ۵۰ میل"
  }]
}
```

سبد ممکن است روزها دست‌نخورده بماند و در این فاصله قیمت عوض شود یا
کالا تمام شود. SKU حذف‌شده یا واریانت پنهان در پاسخ نمی‌آید؛ SKU موجود
اما غیرقابل سفارش با `state: UNAVAILABLE` برمی‌گردد. برای ساخت سفارشی با
انبار صفر، `state: MADE_TO_ORDER` و `max_quantity: 5` است. قیمت صفر یا
نامعتبر قابل سفارش نیست. حداکثر ۳۰ SKU در هر درخواست.

### `GET /api/contact-info`

اطلاعات تماس عمومی برای صفحه «تماس با ما».

```json
{
  "shop_name": "عطر یزد", "shop_name_en": "Yazd Perfume",
  "phone": "03536248000",
  "address": "یزد، خیابان کاشانی، مجتمع تجاری نگین، طبقه دوم",
  "postal_code": "8916945781", "enamad_code": null
}
```

کد اقتصادی و شناسه ملی عمداً برگردانده **نمی‌شوند** — آن‌ها فقط روی
فاکتور رسمی معنا دارند، نه در یک API باز.

### `POST /api/cart/calculate`

```json
{
  "items": [{ "sku": "YZD-0029-EDP-050", "quantity": 1 }],
  "coupon_code": "WELCOME10",
  "province": "یزد", "city": "یزد"
}
```

**قیمت همیشه از دیتابیس خوانده می‌شود.** اگر کاربر
`price_toman` بفرستد، نادیده گرفته می‌شود.

اعتبارسنجی: تعداد باید عدد صحیح ۱ تا ۵۰ باشد، حداکثر ۳۰ قلم.

### `POST /api/orders`

**رزرو ظرفیت کد تخفیف.** اگر سفارش کد تخفیف داشته باشد، ظرفیت
همین‌جا رزرو می‌شود — نه هنگام پرداخت. اگر ظرفیت در همان لحظه پر
شود پاسخ `409` است.

ظرفیت رزروشده هنگام لغو، انقضا یا خطای درگاه آزاد می‌گردد.


```json
{
  "customer_name": "نام کامل",
  "mobile": "09123456789",
  "province": "یزد", "city": "یزد",
  "address": "نشانی کامل", "postal_code": "8916945781",
  "coupon_code": "WELCOME10",
  "items": [{ "sku": "...", "quantity": 1 }]
}
```

موجودی در همان تراکنش کم می‌شود. اگر درگاه خطا دهد، بازمی‌گردد.
سفارش پرداخت‌نشده پس از ۳۰ دقیقه `EXPIRED` و موجودی آزاد می‌شود.

پاسخ شامل `payment_url` است.

### `POST /api/payment/verify`

**idempotent است.** درگاه بانکی گاهی callback را چند بار می‌فرستد؛
تنها اولین فراخوانی اثر دارد.

| وضعیت سفارش هنگام فراخوانی | پاسخ |
|---|---|
| `PENDING` | پردازش می‌شود → `PAID` یا `CANCELLED` |
| `PAID` | `200` «قبلاً پرداخت شده» — بدون تغییر |
| `VERIFYING` | `409` «هم‌اکنون در حال پردازش است» |
| سایر | `409` با نام وضعیت |

`VERIFYING` وضعیت گذراست: پیش از گفت‌وگو با درگاه گرفته می‌شود و در
همان درخواست به `PAID` یا `CANCELLED` می‌رود. کاربر آن را نمی‌بیند.

بدون این قفل، ده callback هم‌زمان موجودی را ده بار آزاد می‌کردند.


```json
{ "order_id": "YZD-...", "result": "success" }
```

در حالت زرین‌پال `authority` لازم است. تأیید دوباره مسدود می‌شود.

### `GET /payment/callback`

بازگشت از درگاه واقعی. تأیید و هدایت به `/payment/result`.

### `POST /api/orders/track`

پیگیری مهمان با هر دو مقدار `{ "mobile": "...", "order_id": "..." }`؛ هر دو الزامی‌اند. `GET` با همین دو پارامتر برای سازگاری باقی است ولی `POST` برای جلوگیری از ثبت شماره در نشانی ترجیح دارد. پاسخ `no-store` فقط اطلاعات لازم پیگیری را دارد و نشانی، یادداشت مشتری یا شناسه بانکی را برنمی‌گرداند. محدودیت نرخ برای IP، تلفن و شناسه سفارش اعمال می‌شود.

### `GET /api/orders/:id/history`

تاریخچه وضعیت. مدیر یا صاحب سفارش.

# علاقه‌مندی و نظرات

### `GET|POST /api/wishlist` — نیازمند ورود

`POST` رفتار تغییر وضعیت دارد: اگر موجود باشد حذف می‌شود.

### `GET /api/reviews/:slug`

```json
{
  "summary": { "count": 12, "avg": 4.3, "longevity": 4.6,
               "sillage": 3.9, "breakdown": { "5": 7, "4": 3 } },
  "reviews": [...],
  "my_review": null,
  "can_review": true,
  "purchased": true
}
```

فقط نظرات تأییدشده. اگر شماره در سفارش پرداخت‌شده باشد،
نشان «خرید تأییدشده» می‌گیرد.

هر نظر `source` دارد: `ONLINE` (خرید آنلاین) یا `INVITED`
(مشتری فروش حضوری با دعوت‌نامه). فرانت برای هر کدام نشان جدا
نشان می‌دهد.

### `POST /api/reviews` — نیازمند ورود

امتیاز ۱ تا ۵، متن حداقل ۱۰ حرف. هر نظر پس از تأیید مدیر منتشر می‌شود.

### `GET /api/review-invite/:token`

دعوت‌نامه نظر برای مشتریان فروش حضوری. **بدون نیاز به ورود** —
خودِ توکن سند هویت است.

```json
{
  "product": { "id": "YZD-0001", "slug": "creed-aventus", "name_fa": "..." },
  "mobile_masked": "0912****11",
  "expires_at": "2026-08-28T…"
}
```

| حالت | پاسخ |
|---|---|
| توکن نامعتبر یا بدشکل | `410` |
| قبلاً استفاده شده | `410` با `used: true` (پیام سپاسگزارانه) |
| منقضی شده | `410` |

### `POST /api/review-invite`

```json
{ "token": "…", "rating": 4, "display_name": "رضا م.",
  "title": "…", "body": "…", "longevity": 4, "sillage": 3 }
```

نظر با `source: 'INVITED'` و `verified: 1` ثبت می‌شود، وضعیت
`PENDING` تا تأیید مدیر. دعوت‌نامه **در همان تراکنش** مصرف
می‌شود — درخواست همزمان با یک توکن فقط یکی می‌گذرد.

### `POST /api/stock-alert`

ثبت شماره برای کالای ناموجود. هنگام افزایش موجودی، پیامک خودکار.

# تیکت و مجله

### `POST /api/tickets`

```json
{
  "order_id": "YZD-MS0N4PNV",
  "product_name": "کرِید — اونتوس",
  "volume_ml": 30,
  "used_under_2ml": true,
  "description": "رایحه با توضیحات سایت مطابقت ندارد"
}
```

| بررسی | خطا |
|---|---|
| حجم > ۱۰ میلی‌لیتر | `400` تنها حجم‌های بالای ۱۰ میلی‌لیتر |
| `used_under_2ml` صحیح | `400` شرط مصرف کمتر از ۲ میلی‌لیتر |
| توضیح ≥ ۱۰ حرف | `400` دلیل مرجوعی را توضیح دهید |
| سفارش وجود دارد | `404` سفارشی با این شماره پیدا نشد |
| وضعیت `SHIPPED` یا `DELIVERED` | `400` هنوز ارسال نشده |
| تیکت باز تکراری ندارد | `409` تیکت باز TKT-… وجود دارد |

پاسخ حداکثر ۲۴ ساعت. اگر کاربر وارد شده باشد شماره‌اش از نشست
برداشته می‌شود، وگرنه از خود سفارش.

### `GET /api/articles?category=` · `GET /api/articles/:slug`

دسته‌ها: `guide` `notes` `video`

# مدیریت

همه نیازمند توکن مدیر.

## نشست
`POST /api/admin/login` · `POST /api/admin/logout` · `GET /api/admin/me`

## سفارش
```
GET /api/orders?q=&status=&page=&limit=
PUT /api/orders/:id/status
```

جستجو در شناسه، نام، موبایل، کد رهگیری و شهر.

چرخه مجاز:
```
PENDING → PAID → PROCESSING → SHIPPED → DELIVERED
                                     ↘ RETURNED
```

هنگام `SHIPPED` می‌توان `tracking_code` و `carrier` داد.
`CANCELLED` و `RETURNED` موجودی را برمی‌گردانند.
هر تغییر پیامک خودکار دارد.

## محصول
```
PUT /api/admin/variants/:sku      { price_toman, stock }
PUT /api/admin/products/:slug     { price_change_percent } یا { set_all_stock }
GET /api/admin/low-stock?threshold=10
```

اگر کالا واقعاً قابل فروش شود و موجودی انبار مثبت باشد، به منتظران اطلاع داده می‌شود؛ واریانت‌های پنهان یا محصولات غیرقابل تأمین اطلاع اشتباه نمی‌دهند.

### قیمت‌گذاری اسانس و نرخ دلار

تمام مبلغ‌های تومانی این بخش به **تومان** هستند. قیمت ورودی هر گرم اسانس
دلاری است؛ مقدار تومانی هر گرم از نرخ دلار محاسبه می‌شود، نه به‌صورت قیمت مستقل.

```
GET  /api/admin/essence-pricing/rate       ← settings.view و products.price
POST /api/admin/essence-pricing/preview    ← settings.edit و products.price
PUT  /api/admin/essence-pricing/rate       ← settings.edit و products.price
```

- پیش‌نمایش: `{ "rate_toman": 300000 }`؛ تعداد محصولات و واریانت‌های تحت تأثیر و حداکثر ۲۰ نمونه قبل/بعد را برمی‌گرداند و تغییری نمی‌دهد.
- اعمال: `{ "rate_toman": 300000, "expected_rate_toman": 250000 }`؛ نرخ مورد انتظار باید همان نرخ دیده‌شده در پیش‌نمایش باشد. در صورت تغییر هم‌زمان نرخ، پاسخ `409` است. نرخ و قیمت‌های واجد شرایط اتمی به‌روز می‌شوند؛ سفارش‌های قبلی تغییر نمی‌کنند.

```
GET  /api/admin/essence-pricing/products/:id
POST /api/admin/essence-pricing/products/:id/preview
PUT  /api/admin/essence-pricing/products/:id
```

هر سه مسیر محصول مجوز `products.price` می‌خواهند. پیش‌نمایش ورودی
`{ "usd_per_gram": "0.286" }` می‌پذیرد و قیمت تومانی هر گرم و قیمت حجم‌ها
را بدون تغییر محاسبه می‌کند. ثبت علاوه بر همان ورودی، `expected_rate_toman`
و `expected_usd_per_kg` دریافتی از پیش‌نمایش را لازم دارد؛ مقدار قبلیِ ثبت‌نشده
باید صریحاً `null` باشد. ناسازگاری پاسخ `409` می‌دهد. در صورت نبود حجم‌های مجاز،
واریانت‌های جدید با موجودی صفر ایجاد می‌شوند؛ وضعیت تأمین محصول تغییر نمی‌کند.
واریانت‌های قدیمی یا عطر مو در محاسبه وارد نمی‌شوند.

### رسانه مقالات

```
GET    /api/admin/media          فهرست تصاویر (آپلودشده + موجود سایت)
POST   /api/admin/media          آپلود تصویر تازه
DELETE /api/admin/media/:name    حذف تصویر آپلودشده
```

مجوز: `content.write` — و برای حذف `content.delete`.

**آپلود** بدنه باینری خام می‌گیرد، نه `multipart`. نام اصلی فایل
در سرآیند `X-File-Name` با `encodeURIComponent` می‌آید.

```bash
curl -X POST https://yazdperfume.ir/api/admin/media \
  -H "Authorization: Bearer TOKEN" \
  -H "Content-Type: image/jpeg" \
  -H "X-File-Name: photo.jpg" \
  --data-binary @photo.jpg
```

پاسخ موفق:

```json
{ "message": "تصویر آپلود شد.", "name": "photo-msh8gt-a1b2c3.jpg",
  "url": "/images/journal/photo-msh8gt-a1b2c3.jpg",
  "size": 84213, "format": "jpg" }
```

قالب از **امضای بایتی** فایل تشخیص داده می‌شود نه از پسوند. تنها
JPG، PNG، WebP و GIF پذیرفته می‌شوند؛ SVG عمداً رد می‌شود چون
می‌تواند اسکریپت داشته باشد. سقف پیش‌فرض ۳ مگابایت.

جزئیات در `ARTICLE_MEDIA.md`.

### `GET /api/admin/reports/csv?days=30`

خروجی گزارش فروش برای اکسل. مجوز: `reports.sales`.

شش بلوک در یک فایل، جدا شده با سطر خالی: خلاصه، فروش روزانه،
پرفروش‌ترین محصولات، تفکیک برند، تفکیک استان، کدهای تخفیف.

```
Content-Type: text/csv; charset=utf-8
Content-Disposition: attachment; filename="yazd-report-30d-2026-08-08.csv"
```

فایل با `\uFEFF` شروع می‌شود؛ بدون آن اکسل فارسی را خراب نشان

**چرا یک فایل و نه شش:** CSV استاندارد یک جدول است، ولی شش
دانلود جدا یعنی شش بار کلیک. اکسل بلوک‌های جداشده با سطر خالی
را در یک برگه نشان می‌دهد.

# هویت مشتری

نام کاربری مشتری **شماره موبایل** است. ورود با رمز عبور؛ پیامک
تنها برای بازیابی رمز به کار می‌رود.

### `POST /api/auth/register`

پس از درخواست کد با `/api/auth/request-code`، نام، شماره، رمز و کد یکبارمصرف به این مسیر فرستاده می‌شود. بدون کد صحیح، هیچ حساب یا نشست ساخته نمی‌شود. کد در تراکنش اتمی فقط یک‌بار مصرف می‌شود؛ حساب موجود دارای رمز از این مسیر بازنویسی نمی‌شود و باید از بازیابی رمز استفاده کند.

### `POST /api/auth/login`
```json
{ "mobile": "09131112233", "password": "..." }
```
پاسخ موفق `{ token, customer }` است. رمز حساب قدیمی تا وقتی شماره با کد تأیید و رمز بازنشانی نشده باشد معتبر شمرده نمی‌شود؛ چنین کاربری از بازیابی رمز یا ورود با کد پیامکی استفاده می‌کند. نشست‌های قدیمی بدون شاهد تأیید، دسترسی مشتری ندارند.

### `POST /api/auth/forgot-password`
```json
{ "mobile": "09131112233" }
```
کد یکبارمصرف پیامک می‌شود. پاسخ برای شماره ثبت‌نشده هم یکسان است.

### `POST /api/auth/reset-password`
```json
{ "mobile": "09131112233", "code": "12345", "new_password": "رمز تازه" }
```
پس از موفقیت، همه نشست‌های دیگر آن مشتری باطل می‌شوند.

### `GET /api/auth/me` · `GET /api/auth/orders` · `POST /api/auth/logout`
نیازمند هدر `Authorization: Bearer <token>`.

## جشنواره و اعلان

### `GET /api/notice`

نوار اعلان فعال بالای سایت. تک‌پیامی و بدون چرخش.

```json
{ "notice": { "id":1, "text":"جشنواره نوروزی — ۲۰٪ تخفیف",
  "link":"/samples", "link_label":"دیدن", "tone":"gold" } }
```

اگر اعلان فعالی نباشد `{"notice": null}` برمی‌گردد.

> **چرا اسلایدر نیست:** پژوهش‌های Notre Dame، Nielsen و
> Conversionista نشان می‌دهند فقط ~۱٪ کاربران روی اسلایدر کلیک
> می‌کنند و ۸۴٪ همان کلیک روی اسلاید اول است. تصویر ثابت در
> آزمون A/B چهل درصد کلیک گرفت در برابر دو درصد اسلایدر. ضمناً
> چرخش خودکار CLS را خراب می‌کند.

### `GET /api/campaigns`

جشنواره‌های فعال، برای نمایش نشان تخفیف روی کارت محصول.

### `GET|POST /api/admin/campaigns` · `PUT|DELETE /api/admin/campaigns/:id`

مدیریت جشنواره — تخفیف خودکار بدون کد.
نیاز: `coupons.view` / `coupons.create` / `coupons.toggle` / `coupons.delete`.

```json
{ "title":"جشنواره نوروزی", "percent":20, "max_discount":500000,
  "scope_families":"woody,citrus", "scope_brands":"کرید",
  "scope_types":"EDP", "scope_gender":"MEN",
  "starts_at":"2026-03-20", "ends_at":"2026-04-02" }
```

هر دامنه‌ای که خالی بماند یعنی «بدون محدودیت». دامنه‌های
پرشده با **و** ترکیب می‌شوند.

اگر چند جشنواره شامل یک کالا شوند، **بهترین** اعمال می‌شود نه
جمعشان. درصد بیش از ۹۰ رد می‌شود.

### `GET|POST /api/admin/notices` · `PUT|DELETE /api/admin/notices/:id`

مدیریت نوار اعلان. با انتشار اعلان تازه، قبلی خودکار خاموش

لینک **فقط داخلی** پذیرفته می‌شود (باید با `/` شروع شود) تا
کسی نتواند بازدیدکننده را به سایت دیگری بفرستد.

### `GET /api/coupons/public?code=SAMPLE20`

اطلاعات نمایشی یک کوپن، برای نشان دادن روی صفحات عمومی.
فقط کوپن فعال، منقضی‌نشده و دارای ظرفیت برمی‌گردد؛ وگرنه ۴۰۴.

هیچ رزروی نمی‌کند و `used_count` یا `active` را لو نمی‌دهد —
اعتبارسنجی واقعی موقع تسویه انجام می‌شود.

```json
{ "code":"SAMPLE20", "type":"PERCENT", "value":20,
  "min_subtotal":300000, "max_discount":300000,
  "description":"تخفیف ویژه سمپل‌ها",
  "per_user_once":true, "remaining":200 }
```

### دامنه کوپن (از مرداد ۱۴۰۵)

`POST /api/admin/coupons` این فیلدهای اختیاری را هم می‌پذیرد:

| فیلد | معنی |
|---|---|
| `scope_families` | فقط این خانواده‌های رایحه (CSV یا آرایه) |
| `scope_brands` | فقط این برندها |
| `scope_types` | `SAMPLE` / `EDP` / `HAIR_MIST` / `BODY_SPLASH` |
| `scope_products` | شناسه محصول مشخص |
| `scope_gender` | `MEN` / `WOMEN` / `UNISEX` |
| `starts_at` | پیش از این تاریخ کار نمی‌کند |
| `max_subtotal` | سقف خرید |
| `first_order_only` | فقط اولین خرید مشتری |
| `assigned_mobile` | کد اختصاصی یک شماره |

**نکته امنیتی:** کوپن دامنه‌دار بدون اقلام سبد رد می‌شود.
دادن تخفیفِ دامنه‌دار روی کل سبد ضرر مستقیم مالی است.

**ترتیب محاسبه:** جشنواره → کوپن. کوپن روی مبلغ پس از جشنواره
حساب می‌شود تا مجموع دو تخفیف از خودِ کالا بیشتر نشود.

### `POST /api/coupons/validate`
```json
{ "code": "WELCOME10", "subtotal": 1200000 }
```
اعتبارسنجی کد تخفیف پیش از تسویه.

### `GET /api/essences`
خانه‌های اسانس (لوزی، ایبرشم، ژیوودان، بل/فیرمنیش) و توضیح هرکدام.
