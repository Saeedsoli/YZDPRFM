# عطر یزد | مرجع فنی پروژه

سند واحد وضعیت واقعی سیستم. هرچه اینجا نوشته شده، تست شده و کار می‌کند.

---

## معماری

**تصمیم:** Node.js خالص با SQLite، بدون فریم‌ورک.

اسناد اولیه پروژه درباره Vendure، MedusaJS و Next.js بودند. هیچ‌کدام
ساخته نشد — آن اسناد در `archive/docs-legacy/` بایگانی شده‌اند.

**چرا بدون فریم‌ورک؟** فروشگاه با ۲٬۱۰۶ محصول و ترافیک متوسط،
به لایه‌های انتزاعی نیاز ندارد. کل بک‌اند ۳٬۴۵۵ خط است و
هیچ وابستگی جز `better-sqlite3` ندارد. استقرار در ۱۵ ثانیه انجام می‌شود.

```
src/
  server.js     ۶۴ Endpoint، مسیریابی، امنیت
  db.js         SQLite، مهاجرت خودکار، نشست، محدودیت نرخ، بکاپ
  payment.js    درگاه قابل‌تعویض (sandbox / زرین‌پال)
  otp.js        ورود با رمز یکبار مصرف
  notify.js     پیامک اطلاع‌رسانی
  seo.js        تزریق متادیتا سمت سرور
  reports.js    گزارش‌های فروش
```

## داده

| مورد | تعداد |
|---|---|
| محصول | ۲٬۱۰۶ |
| متغیر (SKU یکتا) | ۱۴٬۷۴۲ |
| برند | ۱۳۵ |
| مقاله | ۵ |
| جدول دیتابیس | ۲۴ |

**منبع:** فایل `seed/perfumes_catalogue_seed.json` که از دیتاست اصلی
شما ساخته شد. در اولین اجرا خودکار به SQLite منتقل می‌شود.

> پوشه `seed/` عمداً بیرون از `data/` است: لیارا یک دیسک پایدار روی
> `/app/data` سوار می‌کند و هر فایلی که آنجا کپی شده باشد را می‌پوشاند.
> این همان باگ ۲۸ بود که فروشگاه را با صفر محصول بالا می‌آورد.

**فیلدهای حذف‌شده:** `perfumer` و `release_year` در فایل seed
مقادیر ساختگی داشتند (`House Master Perfumer` × ۲۰۶۴). عمداً به
دیتابیس منتقل نشدند تا اطلاعات نادرست به مشتری نمایش داده نشود.

## امنیت — تست‌شده

| تست | نتیجه |
|---|---|
| دستکاری قیمت (۱ تومان) | سرور ۴٬۷۰۰٬۰۰۰ محاسبه کرد |
| API نوشتاری بدون توکن | `401` |
| دو سفارش همزمان، آخرین موجودی | یکی موفق، دومی رد |
| brute-force رمز ادمین | پس از ۶ تلاش `429` |
| تعداد منفی، اعشاری، متنی | همه رد شدند |
| تأیید دوباره پرداخت | مسدود |
| نظر بدون تأیید مدیر | عمومی نشد |

**نشست‌ها در دیتابیس‌اند** — با ری‌استارت Liara کاربران خارج نمی‌شوند.
تست شد: دو فرآیند Node جدا، توکن معتبر ماند.

## نگهداشت خودکار

هر ۵ دقیقه:
- سفارش پرداخت‌نشده قدیمی‌تر از ۳۰ دقیقه → `EXPIRED` و **آزادسازی موجودی**
- حذف نشست و محدودیت منقضی
- پاکسازی لاگ قدیمی‌تر از ۳۰ روز

هر ۲۴ ساعت: پشتیبان با `VACUUM INTO`، نگهداری ۷ نسخه.

## دو چیز باقی‌مانده

هر دو آماده‌اند و فقط اعتبارنامه می‌خواهند:

**۱. درگاه پرداخت**
```bash
PAYMENT_GATEWAY=zarinpal
ZARINPAL_MERCHANT_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```
زرین‌پال کامل پیاده‌سازی شده: درخواست، callback، verify، تبدیل تومان به ریال.

**۲. پیامک**
```bash
SMS_PROVIDER=payamito
SMS_API_KEY=...
```
نیاز به دریافت کلید وب‌سرویس از پنل پیامیتو.

تا آن زمان: درگاه آزمایشی فعال است و کد ورود در لاگ سرور چاپ می‌شود.
