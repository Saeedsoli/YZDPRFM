# نسخه Node.js — ارتقا از ۲۰ به ۲۲

## خلاصه

پروژه روی **Node 22 (Jod, Active LTS)** قفل شد. پیش از این روی
Node 20 بود که **از مارس ۲۰۲۶ EOL شده** و وصله امنیتی نمی‌گیرد.

---

## مسئله‌ای که کشف شد

نسخه Node در **چهار جا** تعریف می‌شود و هیچ‌کدام دیگری را
نمی‌بیند:

| جا | مقدار پیشین | چه کسی می‌خواندش |
|---|---|---|
| `package.json` → `engines.node` | `>=20` | npm (فقط هشدار) |
| `liara.json` → `node.version` | **تعریف نشده** | لیارا (اجرا) |
| `Dockerfile` → `FROM node:` | `node:20-alpine` | فقط اگر `platform=docker` |
| محیط توسعه | v20.20.2 | آزمون‌ها |

### نتیجه: یک ناسازگاری خاموش 🔴

`liara.json` نسخه نداشت، پس لیارا **پیش‌فرض خودش (۲۲)** را
می‌گرفت — در حالی که همه آزمون‌ها روی **۲۰** اجرا می‌شدند.

یعنی کد روی نسخه‌ای آزموده می‌شد که با نسخه اجرا فرق داشت، و
**هیچ آزمونی این را نمی‌گرفت**.

---

## چرا Node 22 و نه چیز دیگر

وضعیت رسمی ([nodejs.org](https://nodejs.org/en/about/previous-releases)،
بررسی‌شده مرداد ۱۴۰۵):

| نسخه | وضعیت | چرا انتخاب/رد شد |
|---|---|---|
| v26 | Current | ❌ شش ماه در معرض تغییر شکننده — برای فروشگاه در حال افتتاح مناسب نیست |
| v24 (Krypton) | LTS | ❌ **لیارا ارائه نمی‌دهد** (سقف ۲۲) |
| **v22 (Jod)** | **Active LTS** | ✅ پشتیبانی تا آوریل ۲۰۲۷ · پیش‌فرض لیارا |
| v20 (Iron) | 🔴 **EOL** | ❌ از مارس ۲۰۲۶ وصله امنیتی نمی‌گیرد |

سایت رسمی Node صریح می‌گوید:

> «Production applications should only use *Active LTS* or
> *Maintenance LTS* releases.»

نسخه‌های موجود در لیارا
([مستندات](https://docs.liara.ir/paas/nodejs/how-tos/choose-version/)):
`8 · 10 · 12 · 14 · 16 · 18 · 20 · 22 (پیش‌فرض)`

> **نکته:** پیشنهاد اولیه «آخرین نسخه استیبل» بود. ولی «آخرین
> استیبل» امروز ۲۶ است که **Current** است نه LTS. برای سامانه‌ای
> که قرار است پول واقعی جابه‌جا کند، LTS انتخاب درست‌تری است.

## آزمون واقعی، نه حدس

به‌جای تغییر کورکورانه و امید به بهترین، **Node 22.23.2 دانلود و
نصب شد** و کل پروژه رویش اجرا گردید:

```
better-sqlite3 روی Node 22
  نصب              ۲ ثانیه (باینری آماده موجود بود، بدون کامپایل)
  SQLite           3.53.2
  تراکنش + WAL     ✓
  متن فارسی        ✓ سالم

کل پروژه روی Node 22.23.2
  bash scripts/smoke_test.sh   →  ۹۸/۹۸ سبز
```

**این مهم‌ترین بخش کار بود.** بدون آن، نخستین آزمون واقعی روی
سرور استقرار انجام می‌شد — جایی که شکست یعنی سایت پایین.

## ریسکی که برطرف شد: وابستگی native

`better-sqlite3` ماژول **native** است و برای هر نسخه Node باینری
جدا می‌خواهد.

```
better-sqlite3@12.11.1  → engines: 20.x || 22.x || 23.x || 24.x || 25.x || 26.x
better-sqlite3@13.x     → engines: >=22
```

### چرا روی نسخه ۱۲ ماندیم

نسخه ۱۳.۰.۲ موجود است، ولی **عمداً ارتقا ندادیم**:

- نسخه ۱۲ هم Node 22 را پوشش می‌دهد (آزموده شد)
- اگر لازم شد به Node 20 برگردیم، نسخه ۱۲ کار می‌کند — نسخه ۱۳ نه
- ارتقای همزمان Node و کتابخانه دیتابیس یعنی اگر چیزی شکست،
  نمی‌دانیم کدام مقصر است

**راه برگشت باز نگه داشته شد.**

## تغییرات

```diff
  package.json
- "engines": { "node": ">=20" }
+ "engines": { "node": ">=22 <23", "npm": ">=10" }

  liara.json
+ "node": { "version": "22" }

  Dockerfile
- FROM node:20-alpine
+ FROM node:22-alpine
```

### چرا `<23` و نه فقط `>=22`

بازه بدون سقف یعنی Node 26 (Current) هم می‌گذرد. برای پروژه‌ای
که فقط روی LTS باید اجرا شود، سقف لازم است.

### چرا `liara.json` نسخه صریح گرفت

اتکا به «پیش‌فرض لیارا» شکننده است: روزی که پیش‌فرض را عوض کنند،
سایت **بدون هیچ هشداری** روی نسخه دیگری اجرا می‌شود.

### چرا Dockerfile هم اصلاح شد

با `platform: node` لیارا آن را **نمی‌خواند** (باگ ۳۹). ولی
سندی که عدد غلط داشته باشد بدتر از نبودنش است — کسی که بعداً
بخواندش گمراه می‌شود.

## نگهبان دائمی

```bash
npm run check-node
```

هر چهار جا را می‌سنجد و ناسازگاری را گزارش می‌کند. به آزمون دود
هم اضافه شد تا هرگز از هم واگرا نشوند.

سه سناریوی خرابی آزموده شد و هر سه گرفته شد:

| سناریو | نتیجه |
|---|---|
| `liara.json` روی ۲۰ | ✓ گرفته شد |
| `engines` بدون سقف | ✓ گرفته شد |
| `liara.json` بدون نسخه | ✓ گرفته شد |

`test_node_platform_deploy.js` هم شش بررسی تازه گرفت (۲۶ → ۳۲)،
از جمله «نسخه انتخابی در دسترس لیارا هست» که مانع می‌شود روزی
نسخه‌ای بنویسیم که لیارا ارائه نمی‌دهد.

## اگر روی لیارا مشکلی پیش آمد

با اینکه محلی آزموده شد، محیط لیارا فرق دارد. اگر
`better-sqlite3` آنجا کامپایل نشد:

```bash
# برگشت فوری — فقط یک فایل
liara env set ... # لازم نیست
# در liara.json:  "node": { "version": "20" }
```

سپس `package.json` را به `">=20 <23"` تغییر دهید و دوباره
مستقر کنید. کد هیچ وابستگی نسخه‌ای ندارد.

> ولی توجه: Node 20 دیگر وصله امنیتی نمی‌گیرد. این راه‌حل موقت
> است، نه دائمی.

## ⚠️ نکته عملیاتی مهم که در آزمون کشف شد

هنگام جابه‌جایی بین Node 20 و 22، خطای زیر رخ داد:

```
Error: ERR_DLOPEN_FAILED
```

**علت:** `better-sqlite3` باینری native دارد که به نسخه دقیق
Node گره خورده است (`NODE_MODULE_VERSION`). `npm install` وقتی
`node_modules` موجود باشد می‌گوید «up to date» و باینری را
**بازسازی نمی‌کند**.

### راه‌حل

```bash
rm -rf node_modules && npm install
```

### چرا روی لیارا مشکلی نیست

لیارا هر استقرار را از صفر می‌سازد — `node_modules` قدیمی وجود
ندارد. این مشکل فقط در محیط توسعه‌ای رخ می‌دهد که نسخه Node
عوض شود.

> **درس:** «npm گفت up to date» ≠ «ماژول native سالم است».
> بررسی واقعی یعنی `require()` کردن، نه اعتماد به خروجی npm.

## آنچه محلی قابل آزمون نبود

محیط توسعه این ورک‌اسپیس همچنان Node 20 است (نسخه ۲۲ دستی
دانلود شد و در `/tmp` است، که ماندگار نیست). یعنی:

- آزمون‌های روزمره روی Node 20 اجرا می‌شوند
- نگهبان `check-node` این را به‌عنوان **هشدار** (نه خطا) گزارش
  می‌کند

این پذیرفته شده است: کد هیچ API مخصوص نسخه‌ای استفاده نمی‌کند و
هر دو نسخه سبز شدند.
