# مدیریت کلیدها و اطلاعات حساس

> این سند در پاسخ به یک سؤال درست نوشته شد:
> «آیا فرستادن کلید سامانه پیامکی و شناسه درگاه در گفتگو با
> دستیار، از نظر امنیتی مشکلی دارد؟»
>
> **پاسخ کوتاه: بله، برای بعضی موارد جدی.**

---

## سه دسته، سه سطح ریسک

### 🔴 هرگز در هیچ گفتگو، تیکت یا ایمیل نفرستید

| مورد | اگر لو برود |
|---|---|
| `SMS_API_KEY` کاوه‌نگار | هر کسی **با اعتبار شما پیامک می‌فرستد** — هزینه مستقیم و سوءاستفاده از نام برند |
| `ADMIN_PASSWORD` | دسترسی کامل: سفارش‌ها، شماره و نشانی مشتریان، قیمت‌ها |
| رمز پنل زرین‌پال / لیارا / پیامیتو | کنترل کامل حساب |
| کد ملی و شناسه ملی واقعی | داده هویتی، مشمول قانون |

**چرا مهم است:** متن گفتگو ذخیره می‌شود، در تاریخچه می‌ماند، و
ممکن است در snapshot ورک‌اسپیس باقی بماند. حتی پاک کردن پیام
تضمینی نیست.

### 🟡 بی‌خطر ولی بی‌فایده

**`ZARINPAL_MERCHANT_ID`** — یک UUID عمومی است که در نشانی هر
تراکنش دیده می‌شود و به‌تنهایی قابل سوءاستفاده نیست.

**کد نماد اعتماد** — کلاً عمومی است و روی فوتر سایت نمایش
داده می‌شود.

ولی فرستادنشان **هیچ کاری پیش نمی‌برد**، چون باید در متغیر
محیطی لیارا ست شوند نه در کد.

### 🟢 مشکلی ندارد

اطلاعات حقوقی که روی فاکتور چاپ می‌شود (نام حقوقی، تلفن، نشانی،
کد پستی). اینها به‌هرحال عمومی می‌شوند — ولی باز هم بهتر است
خودتان در پنل وارد کنید، نه از طریق واسطه.

## اصل معماری: هیچ کلیدی جای کد نیست

همه اسرار از `process.env` خوانده می‌شوند:

```js
const MERCHANT_ID = process.env.ZARINPAL_MERCHANT_ID || '';   // payment.js
const API_KEY     = process.env.SMS_API_KEY || '';            // notify.js, otp.js
const ADMIN_PASSWORD = process.env.ADMIN_PASSWORD || 'yazd1404'; // server.js
```

یعنی **شما اصلاً لازم نیست چیزی به کسی بدهید.** فقط این دستورها
را خودتان بزنید:

```bash
liara env set ADMIN_PASSWORD="یک رمز قوی و یکتا" --app yazdperfume
liara env set PAYMENT_GATEWAY=zarinpal --app yazdperfume
liara env set ZARINPAL_MERCHANT_ID="..." --app yazdperfume
liara env set SMS_PROVIDER=payamito --app yazdperfume
liara env set SMS_API_KEY="..." --app yazdperfume
```

### محافظ‌های موجود

| محافظ | جا |
|---|---|
| `.env` و `.env.*` در `.dockerignore` | اگر روزی فایل ساخته شد، در بسته استقرار نرود |
| `data/yazd.db` در `.dockerignore` | دیتابیس با داده مشتری آپلود نشود |
| هیچ کلیدی در پاسخ API برنمی‌گردد | با آزمون خودکار تضمین شده |
| رمز کارکنان با `scrypt` هش می‌شود | نه SHA — عمداً کند و حافظه‌بر |

> `.gitignore` کافی نیست: **لیارا آن را نمی‌خواند.** تنها
> `.dockerignore` مؤثر است.

## مشکلی که این سؤال آشکار کرد

تا پیش از این، **راهی نبود که مطمئن شوید کلید درست کار می‌کند،
بدون اینکه سفارش واقعی ثبت شود.** اگر شناسه درگاه را اشتباه
می‌زدید، اولین خریدار واقعی با خطا روبه‌رو می‌شد و احتمالاً
برنمی‌گشت.

### راه‌حل: پنل → تنظیمات → بررسی آمادگی افتتاح

دو دکمه:

**بررسی سریع** — بدون تماس با شبکه. می‌گوید چه چیزی ست شده و
چه چیزی نه.

**بررسی کامل** — واقعاً به زرین‌پال وصل می‌شود:

- درگاه: یک درخواست پرداخت ۱۰۰۰ تومانی ساخته می‌شود ولی
  **هیچ‌کس روی لینک نمی‌رود**، پس تراکنشی انجام نمی‌شود و
  خودبه‌خود منقضی می‌گردد. هزینه‌ای ندارد.
- پیامک: **اعتبار حساب** پرسیده می‌شود، نه ارسال پیامک. این
  فراخوانی رایگان است.

**هیچ کلیدی نمایش داده نمی‌شود** — فقط چهار نویسه آخر:
`••••7890` و `••••••••-••••-••••-••••-eeeeee`

### هفت مورد بررسی‌شده

| مورد | سطح |
|---|---|
| اطلاعات حقوقی فاکتور | 🔴 خطا |
| رمز مدیر کل | 🔴 خطا |
| موجودی کالا | 🔴 خطا |
| درگاه پرداخت | 🔴 / 🟡 |
| سرویس پیامک | 🔴 / 🟡 |
| نماد اعتماد | 🟡 هشدار |
| دیسک پایدار | 🟡 هشدار |

## نکته‌ای که با آزمون کشف شد

بررسی اول فقط «خالی نبودن» اطلاعات حقوقی را می‌سنجید. نتیجه:
مقادیر نمونه‌ای که هنگام ساخت پروژه گذاشته شده بودند
(`411358697643`، `14009876543`، `12345`) **سبز می‌شدند** —
در حالی که روی فاکتور واقعی چاپ می‌شوند.

**این از خالی بودن خطرناک‌تر است، چون خالی بودن دست‌کم دیده
می‌شود.**

حالا سه چیز سنجیده می‌شود:
1. خالی نبودن
2. برابر نبودن با مقادیر نمونه
3. درستی قالب (کد اقتصادی ۱۲ رقم، شناسه ملی ۱۱ رقم، کد پستی ۱۰ رقم)

## پیامک آزمایشی واقعی

اگر کاوه‌نگار فعال باشد، جعبه‌ای ظاهر می‌شود که یک پیامک واقعی
به شماره خودتان می‌فرستد. **حداکثر ۵ بار در ساعت** — چون هر
ارسال از اعتبار حساب کم می‌کند.

---

## اگر کلیدی لو رفت

۱. **فوراً از پنل ارائه‌دهنده باطلش کنید** (کاوه‌نگار: پنل →
   کلیدها → حذف · زرین‌پال: پشتیبانی)
۲. کلید تازه بسازید و با `liara env set` جایگزین کنید
۳. `liara restart --app yazdperfume`
۴. صورت‌حساب را بررسی کنید — مصرف غیرعادی نشانه سوءاستفاده است

برای `ADMIN_PASSWORD`: علاوه بر تغییر متغیر محیطی، **از پنل
هم رمز حساب `owner` را عوض کنید.** رمز حساب یک بار هش و ذخیره
می‌شود؛ تغییر متغیر محیطی به‌تنهایی روی حساب موجود اثر ندارد.
این عمدی است تا رمزی که در پنل عوض کرده‌اید با یک ری‌استارت
برنگردد.
