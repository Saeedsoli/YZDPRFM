# راهنمای استقرار روی Liara

دیتابیس در اولین اجرا خودش از `seed/` ساخته می‌شود — نیازی به
مهاجرت دستی یا وارد کردن داده نیست.

> **پیش از شروع، دو نکته که اشتباه‌شان گران تمام می‌شود:**
>
> **۱. پلتفرم `node` یعنی Dockerfile خوانده نمی‌شود.**
> `liara.json` روی `"platform": "node"` است. در این حالت لیارا
> `package.json` را می‌خواند و `npm start` را اجرا می‌کند —
> `Dockerfile` کاملاً نادیده گرفته می‌شود، از جمله `ENV`های داخلش.
> پس هر متغیر محیطی باید با `liara env set` تنظیم شود.
>
> **۲. `.dockerignore` تنها چیزی است که جلوی آپلود دیتابیس محلی
> را می‌گیرد.** لیارا `.gitignore` را نمی‌خواند. بدون
> `.dockerignore`، فایل `data/yazd.db` با تمام سفارش‌های آزمونی
> در بسته می‌رود.
>
> آزمون `node scripts/test_node_platform_deploy.js` هر دو را
> می‌سنجد و بسته را واقعاً می‌سازد و اجرا می‌کند.

---

## گام ۱ — نصب و ورود

```bash
npm install -g @liara/cli
liara login
```

## گام ۲ — ساخت برنامه

```bash
liara create yazdperfume --platform node
```

## گام ۳ — ساخت دیسک پایدار (مهم)

بدون این گام، دیتابیس با هر استقرار مجدد پاک می‌شود.

```bash
liara disk create database --app yazdperfume --size 1
```

در پنل Liara → برنامه → دیسک‌ها، دیسک `database` را به مسیر زیر متصل کنید:

```
/app/data
```

> این کار از قبل در `liara.json` تعریف شده است.

### چرا داده اولیه در `seed/` است و نه `data/`

دیسک پایدار **روی پوشه می‌نشیند و محتوایش را می‌پوشاند**. هر فایلی که
هنگام build داخل `/app/data` کپی شده باشد، پس از mount شدن دیسک دیده
نمی‌شود.

پیش‌تر فایل seed کاتالوگ داخل `data/` بود و نخستین استقرار با پیام
«فایل seed یافت نشد» بالا می‌آمد — فروشگاه با **صفر محصول** شروع
می‌کرد، بدون هیچ خطایی در لاگ.

پس تقسیم کار این است:

| پوشه | محتوا | در تصویر Docker؟ | زیر دیسک؟ |
|---|---|---|---|
| `seed/` | کاتالوگ و مقالات اولیه | بله | **خیر** |
| `data/` | دیتابیس زنده و پشتیبان‌ها | خیر | بله |

اگر روزی `Dockerfile` را دست زدید، **هرگز `COPY data ./data` اضافه
نکنید**. آزمون `scripts/test_cold_deploy.js` این را بررسی می‌کند و
اگر برگردد شکست می‌خورد.

## گام ۴ — متغیرهای محیطی

در پنل Liara → برنامه → تنظیمات → متغیرها:

| متغیر | مقدار | ضروری |
|---|---|---|
| `ADMIN_PASSWORD` | رمز قوی دلخواه شما | **بله** |
| `DB_PATH` | `/app/data/yazd.db` | بله |
| `SITE_URL` | `https://yazdperfume.ir` | برای sitemap |

یا از خط فرمان:

```bash
liara env set ADMIN_PASSWORD="رمز-قوی-شما" --app yazdperfume
liara env set DB_PATH="/app/data/yazd.db" --app yazdperfume
liara env set SITE_URL="https://yazdperfume.ir" --app yazdperfume
```

## گام ۵ — استقرار

```bash
liara deploy --app yazdperfume
```

## چه اتفاقی در اولین اجرا می‌افتد؟

```
[DB] در حال انتقال داده به SQLite ...
[DB] ✅ انتقال کامل شد — 2106 محصول، 14742 متغیر.
[DB] ✅ 5 مقاله منتقل شد.
🌸  عطر یزد | Yazd Perfume
```

سرور به‌صورت خودکار:
1. جدول‌ها را می‌سازد
2. ۲۱۰۶ محصول و ۱۴۷۴۲ متغیر را از `seed/` وارد می‌کند
3. عبارت «(Inspired by)» را پاک می‌کند
4. تصاویر را به محصولات تخصیص می‌دهد
5. مقالات را وارد می‌کند

در اجراهای بعدی، چون دیتابیس روی دیسک پایدار موجود است، مستقیم بالا می‌آید:

```
[DB] SQLite آماده — 2106 محصول موجود.
```

### پیش از استقرار، این را اجرا کنید

```bash
node scripts/test_cold_deploy.js
```

استقرار روی Liara را شبیه‌سازی می‌کند: فقط پوشه‌هایی که `Dockerfile`
کپی می‌کند، به‌علاوه یک `data/` خالی — دقیقاً مثل دیسک تازه. اگر این
آزمون سبز باشد، فروشگاه روی Liara با کاتالوگ کامل بالا می‌آید.

```bash

```

سپس رکورد DNS را طبق راهنمای پنل تنظیم کنید. گواهی SSL خودکار صادر می‌شود.

## عیب‌یابی

**دیتابیس بعد از استقرار خالی است**
دیسک به `/app/data` متصل نشده. گام ۳ را بررسی کنید.

**ورود به پنل مدیریت ممکن نیست**
متغیر `ADMIN_PASSWORD` تنظیم نشده. مقدار پیش‌فرض `yazd1404` است.

**تصاویر نمایش داده نمی‌شوند**
پوشه `public/images/` باید در استقرار وجود داشته باشد؛ در `.gitignore` قرار نگرفته است.

**بیلد به دلیل better-sqlite3 شکست می‌خورد**
`Dockerfile` ابزار کامپایل (`python3 make g++`) را نصب می‌کند. اگر از پلتفرم Node بدون Docker استفاده می‌کنید، Liara به‌صورت خودکار این وابستگی را می‌سازد.
