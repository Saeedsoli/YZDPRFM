## شش کاری که فقط شما می‌توانید

### ۱. اطلاعات تماس ✅ ثبت شد

| فیلد | مقدار |
|---|---|
| شماره تماس | ۰۹۱۳۳۵۰۹۱۷۹ (با واتس‌اپ) |
| نشانی | یزد، خیابان قیام، کوچه بازار محمدعلی‌خان، فروشگاه عطر یزد |
| کد پستی | ۸۹۱۳۶۹۴۸۶۵ |
| نام تحویل‌گیرنده | بابائی |

در فوتر همه صفحات، فاکتور و برچسب پستی دیده می‌شوند. لینک
«پیام در واتس‌اپ» هم خودکار ساخته می‌شود.

> تلفن ثابت ثبت نشده — تصمیم آگاهانه مالک. موبایل با واتس‌اپ
> جایگزین آن است.
>
> ⚠️ اگر اینماد هنگام بررسی تلفن ثابت خواست، آن را در همان فیلد
> وارد کنید؛ لینک واتس‌اپ خودکار حذف می‌شود چون فقط برای
> شماره‌های `09…` ساخته می‌شود.

### ۱-ب. اطلاعات حقوقی — اختیاری

**نام حقوقی · کد اقتصادی · شناسه ملی · شماره ثبت**

طبق تصمیم شما (مرداد ۱۴۰۵)، اینها روی **فاکتور عادی چاپ
نمی‌شوند**. مشتری خرده‌فروشی به آنها نیازی ندارد.

خالی گذاشتنشان کاملاً درست است — بررسی آمادگی هم خطا نمی‌دهد.

فقط اگر خریدار عمده‌ای سند رسمی خواست، آنها را پر کنید و از
دکمه **«فاکتور رسمی»** در پنل (کنار دکمه فاکتور معمولی) استفاده
کنید. نسخه رسمی همه این فیلدها را چاپ می‌کند.

> ⚠️ اگر پرشان کردید، مقدارشان باید **واقعی** باشد. بررسی
> آمادگی مقادیر نمونه را تشخیص می‌دهد و هشدار می‌دهد.

### ۲. رمز مدیر کل

```bash
liara env set ADMIN_PASSWORD="یک رمز قوی" --app yazdperfume
```

پیش‌فرض `yazd1404` است و در مستندات عمومی نوشته شده.

### ۳. درگاه پرداخت

کد کامل آماده است. فقط:

```bash
liara env set PAYMENT_GATEWAY=zarinpal --app yazdperfume
liara env set ZARINPAL_MERCHANT_ID="کد شما" --app yazdperfume
```

تا آن زمان درگاه در حالت سندباکس کار می‌کند و پرداخت واقعی
انجام نمی‌شود.

### ۴. پیامک — سامانه پیامیتو

از پنل پیامیتو، بخش **وب‌سرویس**، این‌ها را بردارید:

```bash
liara env set SMS_PROVIDER=payamito --app yazdperfume
liara env set SMS_API_URL="نشانی وب‌سرویس" --app yazdperfume
liara env set SMS_USERNAME="نام کاربری" --app yazdperfume
liara env set SMS_API_KEY="کلید وب‌سرویس" --app yazdperfume
liara env set SMS_SENDER="شماره خط اختصاصی" --app yazdperfume
```

> **کلید وب‌سرویس بهتر از رمز عبور است** — پیامیتو هر دو را
> می‌پذیرد، ولی با کلید، رمز پنلتان جایی ذخیره نمی‌شود.

بدون این‌ها، کد ورود مشتری در لاگ سرور چاپ می‌شود — برای آزمون
خوب است، برای فروش واقعی نه.

**اگر ساختار درخواست فرق داشت:** متغیرهای `SMS_FIELD_TO`،
`SMS_FIELD_TEXT`، `SMS_FIELD_FROM` و `SMS_AUTH_MODE` قابل تنظیم
هستند — بدون تغییر کد. جزئیات: `docs/SMS_PAYAMITO.md`

**آزمون:** پنل → تنظیمات → بررسی آمادگی → دکمه «پیامک آزمایشی»
با شماره خودتان.

### ۵. موجودی انبار

**موجودی همه کالاها الان صفر است** — یعنی همه «ناموجود». این
عمدی است: کالا تا وقتی انبار تأییدش نکند نباید فروخته شود.

برای وارد کردن موجودی واقعی:

**پنل → محصولات و موجودی**
۱. نام عطر را در کادر جستجو تایپ کنید (نتیجه خودکار می‌آید)
۲. روی «ویرایش» بزنید
۳. برای هر حجم، با دکمه **+** / **−** یا تایپ مستقیم عدد بگذارید

تغییر فوری ذخیره می‌شود. اگر مشتری منتظر آن کالا بوده، همان لحظه
پیامک می‌گیرد و پنل تعدادشان را نشان می‌دهد.

> تا وقتی موجودی صفر است، دکمه خرید در سایت «ناموجود» نشان
> می‌دهد و کسی نمی‌تواند سفارش ثبت کند.

### ۶. پاک‌سازی داده آزمونی ⚠️ فراموش نشود

دیتابیس محلی پر از سفارش‌های آزمونی است («سارا کریمی»، ۸۲ سفارش)
به‌علاوه هزاران ردیف لاگ و ممیزی.

```bash
node scripts/reset_for_launch.js --dry-run   # اول ببینید چه پاک می‌شود
node scripts/reset_for_launch.js --yes       # بعد اجرا کنید
```

سفارش‌ها، مشتریان، نشست‌ها، نظرات، تیکت‌ها، لاگ‌ها و ممیزی پاک
می‌شوند. **کاتالوگ، مقالات، نقش‌ها، کوپن‌ها و تنظیمات دست‌نخورده
می‌مانند.** شماره فاکتور به ۰۰۰۰۱ برمی‌گردد و پیش از هر کاری
پشتیبان گرفته می‌شود.

> اگر روی لیارا از دیسک تازه شروع می‌کنید این قدم لازم نیست —
> `test_node_platform_deploy.js` تأیید می‌کند که بسته استقرار
> اصلاً دیتابیس محلی را نمی‌برد. ولی اگر دیتابیس را دستی آپلود
> می‌کنید، حتماً اول پاک‌سازی کنید.

## زیرساخت

> **نسخه Node:** پروژه روی **۲۲ (Jod, Active LTS)** قفل شده و در
> `liara.json` صریح تعیین شده — نیازی به انتخاب دستی در پنل
> نیست. Node 20 از مارس ۲۰۲۶ EOL است و دیگر استفاده نمی‌شود.
> جزئیات: `docs/NODE_VERSION.md`


```bash
# دیسک پایدار — بدون این، دیتابیس با هر استقرار پاک می‌شود
liara disk create database --app yazdperfume --size 1
# در پنل به /app/data متصل کنید

liara env set DB_PATH=/app/data/yazd.db --app yazdperfume
liara env set SITE_URL=https://yazdperfume.ir --app yazdperfume
liara env set NODE_ENV=production --app yazdperfume
```

> ⚠️ **هرگز `COPY data ./data` به Dockerfile اضافه نکنید.** دیسک
> Liara روی آن سوار می‌شود و فایل seed را می‌پوشاند — فروشگاه با
> صفر محصول بالا می‌آید. `test_cold_deploy.js` این را بررسی می‌کند.

> ⚠️ **`.dockerignore` را حذف نکنید.** `liara.json` پلتفرم را
> `node` گذاشته؛ در این حالت لیارا **Dockerfile را نمی‌خواند** و
> کل پوشه را آپلود می‌کند. تنها چیزی که جلوی رفتن `data/yazd.db`
> (با سفارش‌های آزمونی) را می‌گیرد همین فایل است. `.gitignore`
> کافی نیست — لیارا آن را نمی‌خواند.
> `test_node_platform_deploy.js` این را می‌سنجد.

## بررسی آمادگی — از داخل پنل

پیش از هر چیز، این را ببینید:

**پنل → تنظیمات → بررسی آمادگی افتتاح**

هفت مورد را می‌سنجد و دقیقاً می‌گوید چه چیزی مانده. دکمه
**«بررسی کامل»** واقعاً به زرین‌پال و کاوه‌نگار وصل می‌شود تا
معلوم شود کلیدها درست‌اند — بدون اینکه پرداختی انجام شود یا
پیامکی برود.

> **هیچ کلیدی در پنل نمایش داده نمی‌شود** — فقط چهار نویسه آخر.
> جزئیات امنیتی: `docs/SECRETS_HANDLING.md`

⚠️ **نکته مهم درباره اطلاعات حقوقی:** بررسی فقط «خالی نبودن» را
نمی‌سنجد. مقادیر نمونه‌ای که الان در دیتابیس است
(`411358697643`, `14009876543`, `12345`) **خطا** گزارش می‌شوند،
چون روی فاکتور واقعی چاپ می‌شوند.

## هفته اول پس از افتتاح

### کارکنان

هنوز فقط یک حساب `owner` هست. برای هر همکار حساب جدا بسازید —
رمز مشترک ندهید.

**پنل → کارکنان و نقش‌ها**

نقش‌های آماده: پشتیبان، انباردار، حسابدار، محتوانویس. هر کدام
قابل ویرایش‌اند.

> هر کارمند در نخستین ورود باید رمز اولیه را عوض کند. تا آن
> لحظه پنلش قفل است.

### تحلیل

**پنل → تحلیل بازدید**

مهم‌ترین بخش **قیف خرید** است: می‌بینید مشتری کجا رها می‌کند.
پله‌ای که زیر ۳۰٪ باشد قرمز می‌شود.

گزارش **«جستجوهای بی‌نتیجه»** را هفتگی نگاه کنید — می‌گوید مشتری
چه خواسته که ندارید.

### ویترین

پس از نخستین فروش‌ها، یک بار **تحلیل بازدید → به‌روزرسانی ویترین**
را بزنید تا «منتخب سردبیر» جای خود را به «پرفروش‌ترین‌ها» بدهد.

### تست دستی موبایل

آزمون خودکار موبایل هست، ولی یک بار روی گوشی واقعی سفر خرید را
کامل طی کنید — به‌ویژه مرحله پرداخت.

### نظر مشتریان قدیمی ← بیشترین بازده

فروشگاه با صفر نظر افتتاح می‌شود، در حالی که رقیب اصلی نظر واقعی
دارد. سرمایه ۱۲ سال فروش حضوری شما همین‌جا به کار می‌آید.

**پنل → نظرات → دعوت‌نامه نظر**

شماره مشتری قدیمی + محصول → لینک یکتا + متن آماده پیامک. لینک را
بفرستید؛ خودش نظر می‌نویسد و نشان «خرید حضوری تأییدشده» می‌گیرد.

> **از پرفروش‌ترین ۱۰ محصول شروع کنید، نه از همه ۲٬۱۰۶ تا.**
> ده محصول با پنج نظر واقعی، بسیار مؤثرتر از دویست محصول با یک
> نظر است.

**انتظار واقع‌بینانه:** نرخ پاسخ به درخواست نظر معمولاً ۱۰ تا
۲۰ درصد است. برای ۲۰ نظر روی سایت، حدود ۱۰۰ تا ۲۰۰ دعوت لازم
است. با سابقه شما شدنی است — ولی یک‌شبه نه.

جزئیات کامل: `docs/REVIEW_INVITES.md`

## آنچه عمداً ساخته نشد

این‌ها تصمیم آگاهانه بودند، نه فراموشی:

| مورد | چرا |
|---|---|
| بازیابی رمز فراموش‌شده کارکنان | مدیر باید بازنشانی کند — امن‌تر |
| ورود دومرحله‌ای | پیچیدگی بیش از نیاز فعلی |
| مجوز سطح رکورد | مثلاً «فقط سفارش‌های یزد» — نیاز نبود |
| سبد خرید مهمان | شماره موبایل برای پیگیری لازم است |

اگر روزی لازم شدند، ساختار موجود جا برایشان دارد.
