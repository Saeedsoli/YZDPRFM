# دعوت‌نامه نظر — مشتریان ۱۲ سال فروش حضوری

## مسئله

سامانه نظرات یک در بسته داشت که در نگاه اول دیده نمی‌شد:

```js
// src/server.js — POST /api/reviews
const mobile = otp.mobileFromToken(getCustomerToken(req));
if (!mobile) return sendJSON(401, { error: 'برای ثبت نظر ابتدا وارد شوید.' });
```

و نشان «خرید تأییدشده» از `hasPurchased()` می‌آمد که روی جدول
`orders` کوئری می‌زند.

نتیجه: **مشتری‌ای که ۱۲ سال حضوری خرید کرده، نه حساب کاربری دارد
نه سفارش آنلاین — پس نمی‌تواند نظر بدهد.**

تحلیل رقابتی نشان داده بود عطرسان نظر واقعی دارد و ما نداریم. ولی
سرمایه‌اش را از قبل داشتیم؛ فقط راهی برای ورودش به سایت نبود.

---

## چرا این راه، نه راه ساده‌تر

راه ساده‌تر این بود که مدیر متن نظر را از طرف مشتری در پنل تایپ
کند. رد شد:

| | دعوت‌نامه | ورود دستی توسط مدیر |
|---|---|---|
| نویسنده متن | خود مشتری | فروشگاه |
| ادعای «تأییدشده» | راست | مشکوک |
| اگر کسی بپرسد «سند؟» | لینک یکتا، زمان ثبت، IP | حرف فروشگاه |
| زحمت مدیر | یک پیامک | تایپ کل متن |

تفاوت این دو، تفاوت **شهادت** و **شایعه** است. فروشگاهی که در
صفحه «چرا ما؟» روی صداقت مانور می‌دهد، نمی‌تواند نظر را خودش
بنویسد و نشان تأیید بزند.

---

## چطور کار می‌کند

```
مدیر: پنل → نظرات → دعوت‌نامه
      محصول + شماره مشتری  →  لینک یکتا + متن آماده پیامک
                ↓
      کپی و ارسال برای مشتری
                ↓
مشتری: بازکردن لینک (بدون ورود، بدون رمز)
       نوشتن نظر خودش
                ↓
مدیر: تأیید یا رد  →  انتشار با نشان «خرید حضوری تأییدشده»
```

**عمر لینک:** ۳۰ روز · **یک‌بارمصرف** · **توکن:** ۳۲ نویسه تصادفی

---

## تصمیم‌های امنیتی

**چرا `crypto.randomBytes` و نه شمارنده یا تاریخ**
لینک دعوت عملاً یک کلید دسترسی است. اگر قابل حدس باشد، هر کسی
می‌تواند به‌جای مشتری نظر بنویسد و نشان «تأییدشده» بگیرد — یعنی
همان سازوکاری که قرار بود اعتماد بسازد، تبدیل به ابزار جعل
می‌شود. ۱۶ بایت = ۳۲ نویسه hex.

**چرا مصرف دعوت داخل همان تراکنش ثبت نظر است**
مشتری ممکن است دوبار روی دکمه بزند یا لینک را در دو تب باز کند.
شرط `used_at IS NULL` **داخل خود UPDATE** است، نه یک بررسی جدا —
همان درسی که در کوپن گرفتیم.

> **آزمون‌شده:** ۸ درخواست همزمان با یک توکن → فقط ۱ موفق،
> ۱ نظر در دیتابیس.

**چرا شماره ماسک می‌شود**
مشتری باید مطمئن شود لینک مال خودش است، ولی اگر لینک به دست
دیگری افتاد نباید شماره کامل لو برود. `0912****88`.

**چرا نظر همچنان `PENDING` است**
دعوت‌نامه ثابت می‌کند نظر از مشتری واقعی است، نه اینکه محتوایش
مناسب انتشار است. توهین و تبلیغ همچنان فیلتر می‌شود — ولی
**نظر منفی حذف نمی‌شود** و این روی خود صفحه به مشتری گفته شده.

**چرا دعوت استفاده‌شده حذف نمی‌شود**
حذفش یعنی گم کردن ردِ اینکه آن نظر از کجا آمده. `409` برمی‌گردد.

**چرا مسیر در CORS بسته است**
`/api/review-invite` نوشتاری است. بدون این، سایت دیگری می‌توانست
با توکن دزدیده‌شده نظر ثبت کند.

---

## دو نشان متفاوت، نه یک کاسه

| منشأ | نشان | رنگ |
|---|---|---|
| `ONLINE` | خرید تأییدشده | سبز `#1E8449` |
| `INVITED` | خرید حضوری تأییدشده | کهربایی `#8A6110` |

هر دو خرید واقعی‌اند، ولی سندشان فرق دارد. اگر روزی کسی بپرسد
«این نظر از کجا آمده؟» باید بتوانیم دقیق جواب بدهیم.

## ساختار داده

```sql
CREATE TABLE review_invites (
  id, token UNIQUE, product_id, mobile,
  note,            -- یادداشت داخلی مدیر
  created_by,      -- نام کارمند سازنده
  created_at, expires_at,
  used_at,         -- NULL = هنوز باز
  review_id        -- نظری که با این دعوت ثبت شد
);

ALTER TABLE reviews ADD COLUMN source TEXT DEFAULT 'ONLINE';
```

**مجوز تازه:** `reviews.invite` — به نقش‌های «پشتیبان» و
«محتوانویس» داده شد (مجموع مجوزها: ۳۳ → ۳۴)

## مسیرهای API

```
GET  /api/review-invite/:token     عمومی — بدون ورود
POST /api/review-invite            عمومی — ثبت نظر با توکن

GET    /api/admin/review-invites        reviews.view
POST   /api/admin/review-invites        reviews.invite
DELETE /api/admin/review-invites/:id    reviews.invite
```

`POST` ادمین علاوه بر لینک، **متن آماده پیامک** برمی‌گرداند تا
مدیر چیزی تایپ نکند. هرچه اصطکاک کمتر، احتمال اینکه واقعاً
فرستاده شود بیشتر.

---

## نکته‌های ریز که در بازبینی چشمی درآمد

۱. **`۳۰ روز` با رقم لاتین** در متن پیامک → `faNum()`
۲. **شماره ماسک‌شده لاتین** روی صفحه دعوت → `toFa()`
۳. **`APPROVED` انگلیسی** وسط جدول فارسی پنل → نگاشت فارسی
۴. **شمارنده حرف** بدون بازخورد رنگی → زیر ۱۰ حرف قرمز می‌شود

هیچ‌کدام را آزمون API نمی‌گرفت.

## آنچه هنوز از عهده شماست

**۱. جمع‌آوری شماره مشتریان قدیمی**
سامانه آماده است ولی فهرست مشتری ندارد. از دفتر فروش، پیام‌های
اینستاگرام یا تلگرام شروع کنید.

**۲. ارسال پیامک**
تا وقتی `SMS_API_KEY` تنظیم نشده، پیامک خودکار نمی‌رود. فعلاً
متن آماده را کپی کنید و از تلگرام/واتساپ بفرستید — که حتی بهتر
است، چون پیام شخصی از فروشنده‌ای که می‌شناسند احتمال پاسخ
بیشتری دارد.

**۳. انتظار واقع‌بینانه**
نرخ پاسخ به درخواست نظر معمولاً **۱۰ تا ۲۰ درصد** است. برای
۲۰ نظر واقعی روی سایت، حدود ۱۰۰ تا ۲۰۰ دعوت لازم است. با ۱۲ سال
سابقه این شدنی است، ولی یک‌شبه نه.

> پیشنهاد: از پرفروش‌ترین ۱۰ محصولتان شروع کنید، نه از همه
> ۲٬۱۰۶ تا. ده محصول با پنج نظر واقعی، بسیار مؤثرتر از دویست
> محصول با یک نظر است.
