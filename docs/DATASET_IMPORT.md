```bash
python3 scripts/import_dataset.py --verify   # فقط بررسی، چیزی نمی‌نویسد

شش بررسی اجرا می‌شود و اگر یکی رد شود **هیچ فایلی نوشته نمی‌شود**:

```

✓ هیچ سلول خالی نیست              صفر در ~۵۷٬۰۰۰ سلول

✓ سال عرضه قابل تجزیه است

### 🔴 دام: شماره ردیف با کاما

از ردیف ۱۰۰۰ به بعد شماره‌ها کامادار نوشته می‌شوند (`| 2,111 |`).
الگوی ساده `^\|\s*\d+\s*\|` فقط ۹۹۹ ردیف نخست را می‌گیرد و بی‌صدا
بقیه را رد می‌کند — یعنی گزارش «فایل ناقص است» در حالی که کامل
است.

الگوی درست: `^\|\s*([\d,]+)\s*\|`

### 🔴 دام: کرانِ سال عرضه

## گام ۲ — اعمال روی دیتابیس

### حالت اول: دیتابیس خالی (استقرار تازه)

`seedIfEmpty()` در `src/db.js` خودکار اجرا می‌شود. نیازی به دستور

### حالت دوم: دیتابیس زنده

```bash
node scripts/replace_catalog.js --dry-run   # گزارش
node scripts/replace_catalog.js --yes       # اجرا
```

`seedIfEmpty()` عمداً روی جدول پرشده کار نمی‌کند تا هر بار
راه‌اندازی سرور داده را بازنویسی نکند. برای بازنویسی آگاهانه از
این ابزار استفاده کنید.

#### سیاست جدول‌های وابسته

| جدول | سیاست | چرا |
|---|---|---|
| `order_items` | **دست‌نخورده** | سفارش ثبت‌شده سند مالی است؛ نام محصول در خود ردیف ذخیره شده، پس فاکتور قدیمی درست می‌ماند |
| `wishlist` | پاک | اشاره به محصول ناموجود = ۴۰۴ در حساب کاربری |
| `stock_alerts` | پاک | «خبرم کن» برای SKU ناموجود هرگز فعال نمی‌شود |
| `reviews` | پاک | نظر بدون محصول بی‌معناست |
| `trending` | پاک | آمار بازدید محصول حذف‌شده ویترین را با کالای ناموجود پر می‌کند |
| `product_notes` | بازسازی | از نُت‌های تازه ساخته می‌شود |

**موجودی حفظ می‌شود:** ابزار پیش از پاک‌سازی موجودی‌های غیرصفر را
برمی‌دارد و بعد بازمی‌گرداند (تطبیق با SKU).

## قیمت‌گذاری

### 🔴 قیمت گرمی منبع، قیمت فروش نیست

ستون «قیمت هر ۱ گرم» بهای **اسانس اورجینال** در بازار جهانی است،
نه محصول دست‌ساز عطر یزد.

| | سمپل ۳ میل کرید اونتوس |
|---|---|
| قیمت گرمی خام × ۳ | حدود ۳٬۶۴۰٬۰۰۰ تومان |
| **پس از ضرایب فروشگاه** | **۱۸۴٬۰۰۰ تومان** |

### ضرایب

```
سمپل ۳ml      = گرم × ۰٫۱۲ + ۴۰٬۰۰۰
ادوپرفیوم     = گرم × (حجم÷۱۰) × ۰٫۳۵ + ۱۵۰٬۰۰۰
عطر مو ۱۵۰ml  = گرم × ۵  × ۰٫۲۲ + ۱۲۰٬۰۰۰
بادی ۱۵۰ml    = گرم × ۱۰ × ۰٫۱۲ + ۱۰۰٬۰۰۰
```

قیمت دلاری خام در `variants.price_usd` می‌ماند تا فرمول اختصاصی
آینده بتواند با نرخ روز محاسبه کند. **به مشتری نشت نمی‌کند** —
`attachVariants()` فهرست سفید دارد.

جزئیات → [`PRICING_USD.md`](PRICING_USD.md)

## تصاویر

`reassign_images.js` تصویر هر محصول را بر پایه **خانواده بویایی ×
جنسیت** تخصیص می‌دهد، با هش پایدار روی شناسه محصول (اجرای دوباره
نتیجه یکسان می‌دهد، پس کش مرورگر و ایندکس گوگل نمی‌شکند).

### بازگشت به جنسیت دیگر

چند ترکیب پرجمعیت تصویر اختصاصی ندارند. به‌جای تولید ده‌ها تصویر
تازه، اشتراک **درون همان خانواده بویایی** مجاز است:
`جنسیت خودش ← یونیسکس ← هر جنسیت دیگر`.

دلیلش دقت است نه صرفه‌جویی: تصاویر بر پایه **نُت‌های خانواده**
ساخته شده‌اند (چوبی با تراشه سدر و سنگ، گلی با گل و ابریشم) و
بطری‌ها بی‌نام و خنثی‌اند. یک بطری شیشه‌ای روی بستر چوب سدر، برای
عطر چوبی زنانه هم درست است.

نتیجه: بزرگ‌ترین گروه هم‌تصویر ۱۰۲ محصول · صفر محصول روی تصویر
عمومی `family-*`.

## نکات آزمون

### عدد ثابت ننویسید

آزمون‌ها نباید شمار محصول را سخت‌کد کنند. آزمون امنیتی تزریق SQL
باید «جدول پس از حمله سالم مانده؟» را بسنجد، نه «۲۱۱۱ رکورد
داریم». گره زدن به عدد ثابت یعنی هر به‌روزرسانی کاتالوگ، آزمون
امنیتی را قرمز می‌کند و توجه از خطر واقعی پرت می‌شود.

الگوی درست:

```js
const before = await fetch(`${BASE}/api/products?limit=1`).then(r => r.json());
// ... حمله ...
const after  = await fetch(`${BASE}/api/products?limit=1`).then(r => r.json());
add('تزریق SQL بی‌اثر است', after.total === before.total && after.total > 0);
```

### توزیع تصویر با خی‌دو سنجیده می‌شود

معیار «نسبت بیشینه به کمینه» در نمونه کوچک پرنوسان است. اگر ۳۱۷
محصول را تصادفی بین ۱۰ تصویر پخش کنید، بازه ۲۳ تا ۳۷ کاملاً عادی
است ولی نسبت ۱٫۶۱ می‌شود.

خی‌دو همان چیزی را می‌سنجد که اهمیت دارد: آیا انحراف از یکنواختی
بیش از تصادف است؟ و به تعداد تصاویر هم حساس است.
