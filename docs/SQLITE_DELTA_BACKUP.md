# پشتیبان افزایشی SQLite برای محدودیت فضای ورک‌اسپیس

این ابزار با کتابخانه استاندارد پایتون، یک نسخه سازگار SQLite از دیتابیس باز می‌گیرد، صفحه‌های متفاوت آن را نسبت به پشتیبان کامل gzip ثبت می‌کند و پیش از پذیرش خروجی، بازیابی و صحت دیتابیس را آزمایش می‌کند. هیچ فایلی روی خروجی موجود بازنویسی نمی‌شود. داده پشتیبان ممکن است شامل اطلاعات مشتری باشد و نباید به گیت ارسال شود.

## وابستگی نسخه‌ها

فایل افزایشی **به‌تنهایی پشتیبان کامل نیست** و حتماً به فایل پایه دقیقاً یکسان نیاز دارد. برای نوبت فعلی:

- پایه کامل: `data/backups/pre-reference-v2-20261031.sqlite.gz`
- پیش از ورود شش قیمت: `data/backups/pre-reference-v4-delta-20261031.zip`
- پس از ورود شش قیمت: `data/backups/post-reference-v4-delta-20261031.zip`
- پس از ورود هشت قیمت مرجع بعدی: `data/backups/post-reference-v5-delta-20261031.zip`

پایه و فایل افزایشی باید با هم نگه داشته شوند. در آزمون واقعی، نسخه پس از ورود در فایل جداگانه بازسازی شد و تعداد قیمت‌ها، وضعیت تأمین، اقلام سفارش، هش و `integrity_check` با موفقیت کنترل شدند.

## نمونه اجرای فنی

```bash
python3 scripts/sqlite_delta_backup.py create \
  --db data/yazd.db \
  --base data/backups/pre-reference-v2-20261031.sqlite.gz \
  --output data/backups/new-delta.zip

python3 scripts/sqlite_delta_backup.py restore \
  --base data/backups/pre-reference-v2-20261031.sqlite.gz \
  --delta data/backups/new-delta.zip \
  --output data/backups/restored-check.sqlite
```

مسیر خروجی باید جدید باشد. پس از بازیابی، تنها در محیط جداگانه و با توقف فروشگاه می‌توان درباره جایگزینی دیتابیس تصمیم گرفت؛ جایگزین‌کردن نسخه قدیمی ممکن است سفارش‌های جدیدتر را از دست بدهد. این ابزار برای محیط محلی است و جایگزین پشتیبان‌گیری و بازیابی دیسک پایدار سرور نیست.

## کنترل‌ها

آزمون `scripts/test_sqlite_delta_backup.py` ثبت داده تأییدشده در WAL، بازسازی دقیق، سالم‌بودن SQLite، رد پایه اشتباه، رد فایل دستکاری‌شده و منع بازنویسی خروجی را روی دیتابیس موقت بررسی می‌کند.
