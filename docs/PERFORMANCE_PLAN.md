# سند برنامه‌ریزی عملکرد و سرعت (Performance Plan)
**پروژه:** فروشگاه آنلاین عطر یزد | Yazd Perfume  

با توجه به شرایط متغیر اینترنت در ایران و نوسانات پهنای باند موبایل، معماری فروشگاه بر اصل **"Zero-Latency & Ultra-Light"** استوار شده است تا بالاترین نرخ تبدیل و رضایت مشتری حاصل شود.

---

## ۱. اهداف و بودجه عملکرد (Performance Targets & Metrics)

سنجش‌ها بر اساس شرایط واقعی شبکه ۳G/4G در ایران (موبایل متوسط) تنظیم شده‌اند:

| شاخص عملکرد | هدف کمی (Metric Target) | توضیحات |
|---|---|---|
| **LCP (Largest Contentful Paint)** | **زیر ۱.۸ ثانیه** | زمان بارگذاری اصلی‌ترین عنصر بصری (تصویر عطر یا بنر هیرو) |
| **FCP (First Contentful Paint)** | **زیر ۰.۸ ثانیه** | اولین لحظه‌ای که متن یا رنگی روی صفحه موبایل ظاهر می‌شود |
| **CLS (Cumulative Layout Shift)** | **کمتر از ۰.۰۵** | عدم هرگونه جابه‌جایی ناگهانی المان‌ها هنگام بارگذاری |
| **INP (Interaction to Next Paint)**| **زیر ۱۰۰ میلی‌ثانیه** | پاسخ‌دهی آنی دکمه‌ها و فیلترها به لمس کاربر |
| **حجم کل JS اولیه (JS Bundle Budget)**| **کمتر از ۱۲۰ کیلوبایت (Gzip)**| کنترل شدید کتابخانه‌های فرانت‌اند و حذف کتابخانه‌های سنگین |
| **نمره گوگل لایت‌هاوس (Lighthouse)**| **بالای ۹۲ در موبایل** | سنجش بر روی سرور داخلی لیارا |

## ۲. استانداردهای پردازش و بارگذاری تصاویر (Image Optimization)

1. **فرمت‌های جدید (AVIF & WebP):**
   - تمامی تصاویر آپلود شده در سیستم، اتوماتیک توسط Next.js Image Optimization به فرمت‌های **AVIF** (ویتامین ۵۰٪ کم‌حجم‌تر از JPEG) و **WebP** تبدیل می‌شوند.
2. **ابعاد دقیق و Responsive Images:**
   - کارت‌های محصول: `400x400px` (حجم زیر ۲۵ کیلوبایت).
   - تصاویر گالری محصول (PDP): `800x800px` (حجم زیر ۶۰ کیلوبایت).
   - بنرهای هیرو: `1200x600px` (حجم زیر ۹۰ کیلوبایت).
3. **سیاست بارگذاری تنبل (Lazy Loading):**
   - تمامی تصاویر پایین‌تر از خط دید (Below the Fold) دارای attribute `loading="lazy"` و `decoding="async"` خواهند بود.
   - فقط اولین تصویر هیرو یا اولین کارت محصول دارای `priority={true}` جهت تسریع LCP می‌باشد.
4. **پیش‌نمایش تار (Blur-up Placeholder):**
   - برای جلوگیری از CLS و حس سرعت بالا، هنگام بارگذاری تصویر از Blur Data URI درون SVG/Base64 استفاده می‌شود.

---

## ۳. استانداردهای تایپوگرافی و فونت (Font Subsetting & Hosting)

1. **Self-Hosted کامل:** هیچ فونتی از CDNهای خارجی (Google Fonts یا غیره) بارگذاری نخواهد شد. تمامی فونت‌های فارسی (Yekan Bakh / IranYekan) مستقیماً از دامنه خودمهمان (`/public/fonts/`) فراخوانی می‌شوند.
2. **حذف کاراکترهای اضافه (Font Subsetting):** فایل فونت فقط شامل گلیف‌های فارسی، عربی و انگلیسی به همراه اعداد بومی است (کاهش حجم فایل WOFF2 از ۱۸۰ کیلوبایت به زیر ۳۵ کیلوبایت).
3. **سیاست `font-display: swap`:** متن‌ها بلافاصله با فونت سیستم نمایش داده می‌شوند و پس از ۳۰ میلی‌ثانیه به فونت سفارشی سوئیچ می‌کنند تا FCP به تاخیر نیافتد.

---

## ۴. انیمیشن‌ها و سبک‌سازی کدهای فرانت‌اند

1. **انیمیشن‌های مبتنی بر CSS GPU Hardware Acceleration:**
   - استفاده منحصر به فرد از ویژگی‌های `transform` و `opacity` جهت جلوگیری از Repaint و Reflow مرورگر.
   - عدم استفاده از کتابخانه‌های سنگین انیمیشن (مانند Framer Motion در صفحات اصلی، استفاده از CSS Transitions سبک).
2. **کاهش درخواست‌های HTTP (Minimizing Network Requests):**
   - ادغام آیکون‌ها به صورت embedded SVG درون کد فرانت یا Sprite یکپارچه.
   - استفاده از HTTP/2 و HTTP/3 روی زیرساخت لیارا جهت Multiplexing درخواست‌ها.
