# نماد اعتماد الکترونیک (اینماد)

> وضعیت: **کد پیاده‌سازی شده و آزموده است.** ثبت شناسه در پنل و
> راستی‌آزمایی روی دامنه واقعی، دو کاری است که فقط از عهده مالک برمی‌آید.

---

## کد شما

```
شناسه (id)      580961
کد امنیتی (Code) ZWbXjtwpxxh2fPPh72XCAXEIjFrTLMU8
```

این دو مقدار **محرمانه نیستند** — در نشانی عمومی نشان دیده می‌شوند و
هر بازدیدکننده‌ای می‌تواند ببیندشان. ولی چون مستقیم داخل نشانی تصویر
می‌نشینند، سه لایه محافظ دارند (پایین‌تر توضیح داده شده).

## ثبت — دو دقیقه کار

```
پنل مدیریت → تنظیمات فروشگاه
  شناسه نماد اعتماد (id)  →  580961
  کد امنیتی نماد (Code)   →  ZWbXjtwpxxh2fPPh72XCAXEIjFrTLMU8
  ذخیره تنظیمات
```

**هر دو فیلد باید پر باشند.** با یکی، نشان روی سایت نمی‌آید — نشانی
تصویر هر دو را لازم دارد و نیمه‌کاره یعنی تصویر شکسته. کارت «بررسی
آمادگی» این حالت را **خطا** گزارش می‌کند، نه هشدار.

## چرا کد اینماد را عیناً کپی نکردیم

کدی که اینماد می‌دهد این است:

```html
<a referrerpolicy='origin' target='_blank' href='https://trustseal.enamad.ir/?id=580961&Code=ZWbX…'>
  <img referrerpolicy='origin' src='https://trustseal.enamad.ir/logo.aspx?id=580961&Code=ZWbX…'
       alt='' style='cursor:pointer' code='ZWbX…'>
</a>
```

پنج مشکل دارد:

| مشکل | چرا اهمیت دارد | اصلاح |
|---|---|---|
| `target='_blank'` بدون `rel` | صفحه مقصد از راه `window.opener` به صفحه شما دسترسی می‌گیرد | `rel="noopener"` |
| `alt=''` خالی | صفحه‌خوان نابینایان چیزی نمی‌گوید؛ خودِ اینماد دسترس‌پذیری را می‌سنجد | `alt` گویا + `aria-label` |
| بدون `width`/`height` | تصویر که برسد فوتر می‌پرد — CLS صفر پروژه از بین می‌رود | ابعاد ثابت ۹۶×۹۶ |
| `code='ZWbX…'` روی `<img>` | ویژگی نامعتبر HTML؛ فقط با اسکریپت خودِ اینماد کار می‌کند که ما بار نمی‌کنیم | حذف شد |
| بارگذاری همگام | روی مسیر بحرانی می‌نشیند | ساخت در حافظه، افزودن پس از موفقیت |

## سیاست امنیتی (CSP)

سیاست پیشین سایت `img-src 'self' data: blob:` بود — یعنی مرورگر تصویر
اینماد را **مسدود می‌کرد**. تنها یک دامنه اضافه شد:

```
img-src 'self' data: blob: https://trustseal.enamad.ir
```

**فقط برای تصویر.** `script-src` و `connect-src` دست‌نخورده ماندند، پس
حتی اگر سرور اینماد روزی دستکاری شود نمی‌تواند روی این سایت کد اجرا کند
یا داده بیرون ببرد. بدترین حالت ممکن: تصویر نشان نمی‌آید.

---

## سه لایه محافظ

مقدار از پنل مدیریت می‌آید و داخل نشانی `src` می‌نشیند — همان الگویی که
تزریق می‌سازد. پس سه لایه دارد:

**۱) سرور — `isValidSetting()` در `src/db.js`**

```js
enamad_id:   /^\d{1,10}$/          // فقط رقم
enamad_code: /^[A-Za-z0-9]{8,64}$/ // فقط حرف و رقم
```

فهرست سفید الگو. هر مقداری که دقیقاً نخواند **ذخیره نمی‌شود** — و مدیر
پیام می‌گیرد که کدام فیلد رد شد. سکوت یعنی او فکر کند ثبت شده و روزها
بعد بفهمد نشده.

**۲) مرورگر — `renderEnamad()` در `app.js`**

همان دو الگو دوباره سنجیده می‌شوند. اگر روزی پاسخ API از جای دیگری
بیاید، نشانی تصویر نباید بتواند از کنترل خارج شود.

**۳) کدگذاری — `encodeURIComponent()`**

حتی اگر دو لایه پیشین بیفتند، مقدار پیش از رفتن در نشانی بسته می‌شود.

هفت شکل حمله آزموده شده و همه رد می‌شوند: شکستن ویژگی با کوتیشن، بستن
تگ `img`، نشانی `javascript:`، تغییر دامنه مقصد، شناسه غیرعددی، پارامتر
اضافه، و نویسه کنترلی.

## رفتار در حالت‌های مختلف

| حالت | چه می‌شود |
|---|---|
| هر دو ثبت شده، سرور اینماد سالم | نشان واقعی روی کادر سفید |
| کد ثبت نشده | نشان داخلی «آزمایشی» — سایت ادعای دروغ نمی‌کند |
| فقط یکی ثبت شده | نشان آزمایشی + کارت آمادگی **خطا** می‌دهد |
| سرور اینماد در دسترس نیست | نشان آزمایشی می‌ماند — تصویر شکسته هرگز دیده نمی‌شود |
| شبکه قطع / API خطا | نشان آزمایشی — جعبه خالی نمی‌ماند |

ترتیب رندر عمدی است: **جانشین همیشه اول می‌نشیند**، تصویر واقعی در حافظه
ساخته و آزموده می‌شود، و تنها **پس از موفقیت** جایگزین می‌گردد.

## باگی که آزمون مرورگر گرفت

نسخه اول `loading="lazy"` داشت — همان چیزی که برای کارایی درست به نظر
می‌رسد. آزمون مرورگر نشان داد **صفر درخواست** به سرور اینماد می‌رود:

فوتر پایین صفحه است، پس `lazy` تصویر را تا اسکرول کاربر بار نمی‌کند.
بازدیدکننده‌ای که تا پایین نرود نشان را هرگز نمی‌بیند — یعنی همان چیزی
که برای اعتمادسازی گذاشته‌ایم دیده نمی‌شود. بدتر: چون بار نمی‌شد،
`onerror` هم اجرا نمی‌شد و جانشین در حالت قطعی نمی‌آمد.

**درس:** «کد نوشته شد» ≠ «کد کار می‌کند». خواندن کد این را نمی‌گرفت؛
فقط مرورگر واقعی گرفت.

---

## باگ چهارم: صفحه معلق

ممیزی مستندات یک باگ دیگر را رو کرد. آزمون مرورگرِ PWA ناگهان
شکست خورد با پیام `Timeout: networkidle`.

علت: درخواست تصویر به `trustseal.enamad.ir` در محیط بی‌دسترسی
**هرگز پاسخ نمی‌گرفت و هرگز هم خطا نمی‌داد** — معلق می‌ماند. برای
مرورگر یعنی صفحه هنوز کامل نشده؛ برای کاربر یعنی چرخ «در حال
بارگذاری» در تب، انگار سایت خراب است.

این فقط مشکل سندباکس نیست: اگر سرور اینماد کند شود یا کاربری پشت
فیلتر باشد، همین اتفاق در تولید می‌افتد.

**راه‌حل:** مهلت ۸ ثانیه. پس از آن `img.src = ''` درخواست معلق را
رها می‌کند و جانشین سر جایش می‌ماند. یک پرچم `settled` جلوی
اجرای همزمان مهلت و `onload` را می‌گیرد.

اندازه‌گیری‌شده: صفحه‌ای که پیش‌تر برای همیشه معلق می‌ماند، حالا
**پس از ۸٫۹ ثانیه** آزاد می‌شود.

---

## دو باگ که فقط تصویر مرورگر گرفت

نخستین تصویر از فوتر نشان داد کادر سفید **تمام عرض ستون** را گرفته —
۳۵۰ پیکسل دور تصویری ۹۶ پیکسلی. علت: قاعده عمومی
`.footer-grid a { display:block }` بر `display:inline-block` نشان غلبه
می‌کرد. همان قاعده روی `:hover` یک `padding-right:5px` می‌گذاشت که
کادر را کج می‌کرد.

اندازه‌گیری دوم مشکل دیگری نشان داد: `#enamadSeal` در حالت نشان ۱۱۸
پیکسل و در حالت جانشین ۱۱۰ پیکسل بود — ۸ پیکسل پرش هنگام جایگزینی.
`min-height` به `height` ثابت با چیدمان انعطافی تغییر کرد.

**هیچ‌کدام را آزمون متنی نمی‌گرفت**، چون خودِ قاعده‌ها درست نوشته شده
بودند؛ قاعده دیگری بر آن‌ها غلبه می‌کرد. این را فقط اندازه‌گیری DOM
واقعی نشان می‌دهد.

```

test_pwa_browser.py      سبز     تأیید اینکه صفحه دیگر معلق نمی‌ماند
smoke_test.sh           ۱۰۲/۱۰۲
```

حالت‌های آزموده‌شده در مرورگر:

```
نشان سالم          → تصویر واقعی
سرور قطع           → جانشین، بدون تصویر شکسته
سرور کند (معلق)    → جانشین پس از ۸ ثانیه، صفحه آزاد
کد ثبت‌نشده        → جانشین «آزمایشی»
فقط یک بخش ثبت‌شده → جانشین، نشانی ناقص ساخته نمی‌شود
```

ابعاد اندازه‌گیری‌شده در مرورگر:

```
جعبه نشان    ۳۵۰×۱۱۰   (هر دو حالت — یکسان)
کادر سفید    ۱۱۰×۱۱۰   (مربع، دور تصویر)
تصویر        ۹۶×۹۶
CLS          ۰٫۰۰۰۰
```

آزمون مرورگر درخواست به `trustseal.enamad.ir` را **رهگیری** می‌کند و
PNG ساختگی برمی‌گرداند — چون سرور اینماد روی `localhost` نشان نمی‌دهد.
این دقیقاً همان مسیری را می‌آزماید که در تولید طی می‌شود، بدون وابستگی
به شبکه.

**CLS اندازه‌گیری‌شده پس از افزودن نشان: ۰٫۰۰۰۰**

## آنچه فقط از عهده شما برمی‌آید

**۱) ثبت شناسه در پنل** — دو دقیقه، بالاتر توضیح داده شد.

**۲) راستی‌آزمایی روی دامنه واقعی.** اینماد نشان را **فقط روی دامنه
ثبت‌شده** نمایش می‌دهد. روی `localhost` تصویر نمی‌آید و این خرابی نیست.
پس از استقرار روی `yazdperfume.ir`:

- فوتر را باز کنید و ببینید نشان واقعی آمده، نه «آزمایشی»
- روی نشان کلیک کنید — باید پرونده شما در سایت اینماد باز شود
- اگر «آزمایشی» ماند: کنسول مرورگر را باز کنید و دنبال پیام CSP بگردید

**۳) الزامات دیگر اینماد.** نشان تنها بخشی از ماجراست. اینماد این‌ها را
هم می‌خواهد و همه از قبل روی سایت هستند:

| الزام | وضعیت |
|---|---|
| نشانی پستی و کد پستی در همه صفحات | ✅ فوتر |
| شماره تماس | ✅ فوتر |
| صفحه قوانین و مقررات | ✅ `/terms` |
| صفحه حریم خصوصی | ✅ `/privacy` |
| شرایط مرجوعی | ✅ `/terms` و فوتر |
| قیمت شفاف بدون هزینه پنهان | ✅ هیچ مالیات یا کارمزدی افزوده نمی‌شود |
