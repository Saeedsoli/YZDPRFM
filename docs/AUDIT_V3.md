## بخش ۲ — یافته‌های جدید این ممیزی 🆕

### 🔴 ۱. نشست‌ها در حافظه — با ری‌استارت همه خارج می‌شوند
```js
const adminSessions = new Map();   // server.js
const sessions = new Map();        // otp.js
```
Liara روزانه چند بار ری‌استارت می‌کند (استقرار، به‌روزرسانی، مقیاس‌دهی).
هر بار **تمام مشتریان واردشده و ادمین از حساب خارج می‌شوند**.
مشتری وسط تسویه‌حساب، ناگهان به صفحه ورود پرتاب می‌شود.

**راه‌حل:** ذخیره نشست در جدول SQLite.

### 🔴 ۲. بدون محدودیت نرخ — آسیب‌پذیر به حمله
تست شد:
```
۱۰ تلاش رمز اشتباه پشت‌سرهم → هیچ مسدودسازی
۳ درخواست OTP برای شماره‌های مختلف → همه پذیرفته شد
```
- رمز ادمین قابل حدس زدن با brute-force است
- با پیامک واقعی، حمله OTP یعنی **هزینه مستقیم مالی** (هر پیامک پول است)

**راه‌حل:** محدودیت بر اساس IP و شماره.

### 🔴 ۳. سفارش‌های رهاشده موجودی را قفل می‌کنند
تست شد: یک سفارش `PENDING` باقی ماند و موجودی‌اش آزاد نشد.

اگر کاربر به درگاه برود و پنجره را ببندد، کالا برای همیشه رزرو می‌ماند.
در فروش محدود، این یعنی **از دست دادن فروش واقعی**.

**راه‌حل:** کار زمان‌بندی‌شده که سفارش‌های `PENDING` قدیمی‌تر از ۳۰ دقیقه را لغو کند.

### 🟠 ۴. تعداد منفی پذیرفته می‌شود
```
{"quantity": -5}  →  پذیرفته شد
```
در `validateCart` از `Math.max(1, ...)` استفاده شده که آن را به ۱ تبدیل می‌کند،
پس ضرر مالی ندارد — اما ورودی نامعتبر باید صریحاً رد شود.

### 🟠 ۵. SEO صفحه محصول ضعیف است
- **بدون Open Graph** — اشتراک در تلگرام و واتساپ پیش‌نمایش ندارد
- **بدون Schema.org Product** — گوگل قیمت و موجودی را در نتایج نشان نمی‌دهد
- **رندر کلاینت‌ساید** — عنوان در HTML خام `صفحه محصول` است، نه نام عطر

sitemap ۲٬۱۱۴ لینک دارد ولی هر ۲٬۱۰۶ صفحه محصول عنوان یکسان دارند.

### 🟠 ۶. تصاویر بهینه نشده
| مورد | حجم |
|---|---|
| تصاویر محصول | ۱.۴ مگابایت |
| `scene-linen.jpg` | ۲۴۱ کیلوبایت (یک تصویر) |
| بنرهای قدیمی | ۱.۳ مگابایت |
| نسخه WebP | **۰** |

WebP معمولاً ۳۰–۵۰٪ کوچک‌تر است. برای اینترنت موبایل ایران مهم است.

### 🟠 ۷. دسترس‌پذیری تقریباً صفر
```
index.html    → alt:0  aria:0
checkout.html → alt:0  aria:0
```
بدون `aria-label`، بدون `alt` معنادار. برای کاربران کم‌بینا غیرقابل استفاده.

### 🟡 ۸. لاگ و پایش وجود ندارد
- خطاها فقط در `console` — با ری‌استارت پاک می‌شوند
- بدون فایل لاگ، بدون تاریخچه خطا
- اگر فردا مشتری بگوید «پرداختم نشد»، هیچ ردی نداریم

### 🟡 ۹. بکاپ خودکار نیست
دیتابیس روی دیسک Liara است. اگر خراب شود یا اشتباهی حذف شود، **همه‌چیز از دست می‌رود**.

### مدیریت محصول در پنل

## جمع‌بندی

**آنچه داریم:** یک فروشگاه عملیاتی کامل. منطق کسب‌وکار درست است، امنیت پایه برقرار است، و تست همزمانی را با موفقیت گذراند.

**شکاف اصلی:** پروژه برای «کار کردن» ساخته شده، اما برای «زنده ماندن در تولید» هنوز سه چیز کم دارد — نشست پایدار، محدودیت نرخ، و آزادسازی موجودی.

**مهم‌ترین کمبود عملیاتی:** نبود مدیریت محصول در پنل. شما نمی‌توانید بدون دسترسی به دیتابیس، قیمت یک عطر را عوض کنید یا موجودی را به‌روز کنید. برای فروشگاه واقعی این روزمره‌ترین کار است.

**فاصله تا افتتاح:** پنج مورد فاز A. هیچ‌کدام بزرگ نیستند.
