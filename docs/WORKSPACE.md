# وضعیت ورک‌اسپیس — پس از مرتب‌سازی

**تاریخ: ۲۱ آبان ۱۴۰۵**

این سند نقشه پوشه‌هاست تا بدانیم هر چیزی کجاست و چه چیزی بخشی از فروشگاه است و چه چیزی نیست.

## ریشه پروژه (این‌ها بخشی از فروشگاه‌اند)

| مسیر | چیست |
|---|---|
| `src/` | کد سرور، مسیرها، ماژول‌ها |
| `public/` | صفحه‌ها، استایل، فونت، تصاویر، ویدیوی هدر |
| `seed/` | داده اولیه، مصوبات، فهرست لوگو و تصاویر نمادین |
| `scripts/` | آزمون‌ها و ابزارها |
| `docs/` | مستندات فنی و عملیاتی |
| `data/` | دیتابیس محلی و پشتیبان‌ها — **هرگز به Git یا بسته استقرار نمی‌رود** |
| `uploads/` | پیوست‌های کاربر — از Git و بسته استقرار مستثنا |
| `reports/` | گزارش‌های تحلیل قیمت و پوشش |

## پوشه‌های کاری (در Git نیستند)

| مسیر | چیست | در بسته استقرار؟ |
|---|---|---|
| `design/approved-previews/` | نمونه‌هایی که تأیید و پیاده شدند | نه |
| `design/rejected-previews/` | نمونه‌هایی که رد شدند — سابقه تصمیم | نه |
| `design/proofs/` | اسکرین‌شات‌های اثبات تغییرات (WebP) | نه |
| `deliverables/` | بسته‌های ZIP استقرار ساخته‌شده | نه |
| `source/` | تصاویر و فونت خام برای بازتولید دارایی‌ها | نه |

## سابقه رسمی در Git

`previews/` تنها سابقه‌ای است که در مخزن می‌ماند: نمونه‌های تأییدشده‌ای که به کد رسیدند. `design/` یادداشت کاری است و در Git نمی‌رود.

## قاعده نگهداری

- نمونه‌های تأییدشده می‌مانند تا سابقه تصمیم بماند؛ نمونه‌های رد‌شده کنار گذاشته می‌شوند.
- اسکرین‌شات‌های اثبات به WebP تبدیل می‌شوند تا ورک‌اسپیس سبک بماند.
- تصاویر خام تولیدی (PNG بزرگ) از `public/` بیرون می‌روند؛ فقط نسخه WebP/JPEG بهینه سرو می‌شود.
- هر چیزی که خروجی ساخت است (ZIP، اسکرین‌شات، نمونه طراحی) در `.gitignore` و `.dockerignore` هست.
