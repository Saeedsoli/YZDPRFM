# عطر یزد | Yazd Perfume

فروشگاه آنلاین عطرهای دست‌ساز — ۲٬۱۰۶ رایحه بازآفرینی‌شده از ۱۳۵ خانه عطر معتبر جهان.

---

> **فهرست کامل مستندات:** `docs/README.md`
>
> **مرجع فنی:** `docs/PROJECT_REFERENCE.md` — وضعیت واقعی سیستم،
> نتایج تست امنیتی و عملکرد، و چک‌لیست پیش از افتتاح.

## اجرا روی سیستم محلی

```bash
npm install
npm start
```

سرور روی `http://localhost:3000` بالا می‌آید.
در اولین اجرا، دیتابیس SQLite به‌صورت خودکار از فایل seed ساخته می‌شود.

**رمز پیش‌فرض پنل مدیریت:** `yazd1404`
(حتماً روی سرور واقعی از طریق متغیر `ADMIN_PASSWORD` تغییر دهید)

---

## استقرار روی Liara

```bash
liara deploy
```

تنظیمات در `liara.json` از پیش آماده است و شامل یک **Disk پایدار** برای دیتابیس می‌شود.

### متغیرهای محیطی لازم

| متغیر | مقدار | توضیح |
|---|---|---|
| `ADMIN_PASSWORD` | رمز دلخواه | رمز ورود پنل مدیریت |
| `DB_PATH` | `/app/data/yazd.db` | مسیر دیتابیس روی Disk |
| `SITE_URL` | `https://yazdperfume.ir` | برای sitemap |

### ساخت Disk در Liara

```bash
liara disk create database --size 1
```

سپس در پنل Liara، دیسک را به مسیر `/app/data` متصل کنید.
با این کار دیتابیس در ری‌استارت و استقرار مجدد **حفظ می‌شود**.

### چرا `seed/` جدا از `data/` است

روی لیارا یک Disk پایدار روی `/app/data` سوار می‌شود. هر فایلی که
هنگام ساخت تصویر داخل آن پوشه کپی شده باشد، پس از سوار شدن دیسک
**دیده نمی‌شود** — دیسک خالی رویش می‌نشیند.

وقتی فایل اولیه داخل `data/` بود، نخستین استقرار با خطای «فایل
seed پیدا نشد» شکست می‌خورد.

> ⚠️ هرگز `COPY data ./data` به `Dockerfile` اضافه نکنید.

### چرا `source/` در استقرار نمی‌رود

۱۵ مگابایت منبع خام است که خروجی نهایی‌شان از قبل در `public/`
هست. روی سرور هیچ مصرفی ندارند و فقط بسته را سنگین می‌کنند.
برای بازتولید تصاویر یا فونت‌ها روی ماشین توسعه لازم‌اند.

## قوانین کسب‌وکار (پیاده‌سازی‌شده)

**ارسال**
- سراسر کشور: ۳۵۰٬۰۰۰ تومان
- شهر یزد: ۲۵۰٬۰۰۰ تومان
- رایگان برای خرید بالای ۲٬۵۰۰٬۰۰۰ تومان
- تحویل ۳ تا ۷ روز کاری

**مرجوعی**
- فقط حجم بالای ۱۰ میلی‌لیتر
- مصرف کمتر از ۲ میلی‌لیتر
- عدم قرارگیری در معرض نور و آسیب
- پاسخ حداکثر ۲۴ ساعت

**شفافیت**
تمام محصولات بازآفرینی دست‌ساز هستند و ادعای اورجینال بودن ندارند.

**چرخه وضعیت سفارش**

```
در انتظار پرداخت → پرداخت شده → در حال آماده‌سازی → ارسال شده → تحویل داده شده
                                                              ↘ مرجوع شده
```

تغییر وضعیت فقط در مسیر مجاز ممکن است. در هر مرحله پیامک خودکار
برای مشتری ارسال می‌شود. لغو یا مرجوعی، موجودی را بازمی‌گرداند.

**کد تخفیف**

سه نوع پشتیبانی می‌شود: درصدی (با سقف)، مبلغ ثابت، و ارسال رایگان.
برای هر کد می‌توان حداقل خرید، محدودیت تعداد، تاریخ انقضا و
«یک‌بار برای هر مشتری» تعریف کرد. اعتبارسنجی همیشه سمت سرور
دوباره انجام می‌شود.

کدهای نمونه: `WELCOME10` `SAMPLE20` `FREESHIP` `YAZD200`

## امنیت

- قیمت‌ها **همیشه** از دیتابیس خوانده می‌شوند؛ ورودی کاربر نادیده گرفته می‌شود
- تمام مسیرهای نوشتاری مدیریت با توکن محافظت می‌شوند
- موجودی هنگام سفارش کم و هنگام لغو بازگردانده می‌شود
- اعتبارسنجی شماره موبایل ایرانی
- **نشست‌ها در دیتابیس** — با ری‌استارت سرور کاربران خارج نمی‌شوند
- **محدودیت نرخ** روی ورود، درخواست کد و ثبت سفارش
- اعتبارسنجی سخت‌گیرانه تعداد (عدد صحیح، ۱ تا ۵۰، حداکثر ۳۰ قلم)
- لاگ ماندگار رویدادها و خطاها با نگهداشت ۳۰ روزه

### محدودیت‌های نرخ

| مورد | حد مجاز | پنجره | مسدودی |
|---|---|---|---|
| ورود ادمین | ۶ بار | ۱۰ دقیقه | ۱۵ دقیقه |
| درخواست کد (هر IP) | ۱۲ بار | ۱ ساعت | ۳۰ دقیقه |
| درخواست کد (هر شماره) | ۵ بار | ۱ ساعت | ۱ ساعت |
| ثبت سفارش | ۱۰ بار | ۱۰ دقیقه | ۱۰ دقیقه |

### نگهداشت خودکار

هر ۵ دقیقه اجرا می‌شود:
- سفارش‌های پرداخت‌نشده قدیمی‌تر از ۳۰ دقیقه → وضعیت `EXPIRED` و **آزادسازی موجودی**
- حذف نشست‌ها و محدودیت‌های منقضی
- پاکسازی لاگ‌های قدیمی‌تر از ۳۰ روز

مدت انتظار با `PENDING_ORDER_TTL_MIN` قابل تنظیم است.

### پشتیبان‌گیری خودکار

هر ۲۴ ساعت یک نسخه در `data/backups/` ساخته می‌شود و ۷ نسخه آخر
نگه داشته می‌شود. از `VACUUM INTO` استفاده می‌شود که حتی حین
نوشتن، نسخه سازگار می‌سازد.

```
BACKUP_INTERVAL_HOURS=24   # فاصله
BACKUP_KEEP=7              # تعداد نسخه
```

دانلود دستی از پنل مدیریت → ابزارها.

## سئو و کارایی

**متادیتا سمت سرور** — چون خزنده‌های گوگل، تلگرام و واتساپ
جاوااسکریپت اجرا نمی‌کنند، `seo.js` پیش از ارسال HTML عنوان و
متا را با داده واقعی جایگزین می‌کند:

- عنوان یکتا برای هر ۲٬۱۰۶ صفحه محصول
- توضیح شامل نُت‌های بویایی و قیمت
- Open Graph برای پیش‌نمایش در شبکه‌های اجتماعی
- Schema.org Product با قیمت و موجودی (نمایش در نتایج گوگل)
- BreadcrumbList و OnlineStore
- صفحه اختصاصی هر مقاله با Schema.org Article

**نشانی خوانا** — مقالات با slug فارسی ساخته می‌شوند
(`/journal/راهنمای-انتخاب-عطر`). هنگام ویرایش عنوان، slug
حفظ می‌شود تا لینک‌های ایندکس‌شده در گوگل نشکنند.

**۴۰۴ درست** — مسیرهای `/perfume/:slug` و `/journal/:slug`
پیش از سرو صفحه، وجود رکورد را در دیتابیس بررسی می‌کنند.
آدرس نامعتبر واقعاً ۴۰۴ برمی‌گرداند، نه صفحه خالی با کد ۲۰۰.

**فشرده‌سازی gzip** — پاسخ‌های بالای ۱ کیلوبایت فشرده می‌شوند.

| مسیر | خام | gzip | کاهش |
|---|---|---|---|
| صفحه اصلی | ۱۴٬۵۵۸ | ۴٬۷۵۸ | ۶۷٪ |
| API کاتالوگ | ۱۱٬۸۵۰ | ۱٬۹۶۵ | ۸۳٪ |
| sitemap | ۲۲۷٬۲۸۶ | ۹٬۹۷۲ | **۹۶٪** |

**پاسخ سبک کاتالوگ** — فهرست محصولات تنها فیلدهای لازم کارت را
می‌فرستد، نه هر ۷ متغیر را. حجم از ۸۰ به ۱۲ کیلوبایت رسید.
پنل مدیریت با `?full=1` نسخه کامل می‌گیرد.

**جستجوی یکسان‌سازی‌شده** — ستون `search_blob` ایندکس‌شده
همه فیلدها را یکجا دارد. متن با حذف اعراب و یکسان‌سازی
حروف عربی نرمال می‌شود:

```
کرید   →  ۲۶ نتیجه
کرِید  →  ۲۶ نتیجه
كريد   →  ۲۶ نتیجه
```

جستجوی چندواژه‌ای هم پشتیبانی می‌شود («تام فورد چوبی»).
زمان پاسخ زیر ۵ میلی‌ثانیه.

**تصاویر WebP** — سرور بر اساس هدر `Accept` نسخه مناسب را
ارائه می‌کند. مرورگرهای قدیمی همچنان JPEG می‌گیرند.

| | JPEG | WebP | صرفه‌جویی |
|---|---|---|---|
| مجموع تصاویر | ۲٬۶۵۳ KB | ۱٬۲۵۵ KB | **۵۳٪** |

**تاب‌آوری شبکه** — همه صفحاتی که از API داده می‌گیرند، در صورت
قطع اینترنت پیام روشن و دکمه «تلاش دوباره» نشان می‌دهند،
نه اسپینر بی‌پایان.

**کدهای پاسخ درست** — خطای ورودی کاربر (JSON خراب، ساختار
نامعتبر) کد ۴۰۰ با پیام فارسی می‌گیرد، نه ۵۰۰. این خطاها در
لاگ سیستم ثبت نمی‌شوند تا خطاهای واقعی گم نشوند.

**موبایل** — هدف لمسی حداقل ۴۴ پیکسل روی صفحه‌های لمسی،
احترام به حاشیه امن آیفون، اندازه ۱۶ پیکسل برای ورودی‌ها
تا سافاری هنگام تایپ زوم نکند، و زوم دستی در همه صفحات آزاد است.

**دسترس‌پذیری** — لینک پرش به محتوا، `aria-label` روی فرم‌ها و
دکمه‌ها، `role` و `aria-live` برای تغییرات پویا، حلقه فوکوس
مشخص، و احترام به `prefers-reduced-motion`.

## تجربه مشتری

**علاقه‌مندی** — نشان قلب در صفحه محصول، صفحه اختصاصی `/wishlist`،
و شمارنده در حساب کاربری. نیازمند ورود.

**نظرات و امتیاز** — امتیاز ۱ تا ۵ به‌همراه سنجش جداگانه
ماندگاری و پخش بو. نظر کسانی که محصول را خریده‌اند با نشان
«خرید تأییدشده» متمایز می‌شود. هر نظر پیش از انتشار توسط
مدیر بررسی می‌شود و فروشگاه می‌تواند پاسخ عمومی بدهد.
میانگین امتیاز در صفحه محصول و در Schema.org نمایش داده می‌شود.

**اطلاع موجود شدن** — برای کالاهای ناموجود، مشتری شماره‌اش را
ثبت می‌کند و به‌محض اینکه مدیر موجودی را افزایش دهد، پیامک
خودکار ارسال می‌شود.

## گزارش‌های مدیریتی

داشبورد `/admin` → تب «گزارش فروش» با بازه‌های ۷، ۳۰ و ۹۰ روز:

- فروش، تعداد سفارش، میانگین سبد و **درصد رشد** نسبت به بازه قبل
- نمودار خطی روند فروش (SVG خالص، بدون کتابخانه خارجی)
- نرخ تبدیل: نسبت سفارش پرداخت‌شده به کل
- پرفروش‌ترین محصولات، تفکیک برند، نوع محصول و استان
- مشتریان وفادار بر اساس مجموع خرید
- عملکرد هر کد تخفیف: دفعات استفاده، تخفیف داده‌شده، فروش حاصل
- ارزش کل موجودی انبار و شمار کالاهای ناموجود

## فاکتور و برچسب پستی

**چرا HTML و نه PDF؟** کتابخانه‌های تولید PDF در Node با حروف
چسبان فارسی و راست‌به‌چپ مشکل دارند. صفحه چاپ‌پذیر HTML با
فونت وزیرمتن، خروجی تمیزتری می‌دهد و مرورگر خودش PDF می‌سازد.

**فاکتور** `/invoice?order=YZD-...`
- شماره ترتیبی یکتا که فقط یک‌بار صادر می‌شود
- اطلاعات حقوقی فروشنده از تنظیمات
- تفکیک تخفیف و هزینه ارسال
- **مبلغ به حروف فارسی**
- مهر «پرداخت شد» برای سفارش‌های تسویه‌شده
- قالب A4 با CSS مخصوص چاپ

**برچسب پستی** `/label?order=YZD-...`
- ابعاد استاندارد ۱۰۰×۱۵۰ میلی‌متر
- گیرنده، فرستنده، محتویات
- بارکد تولیدشده از کد رهگیری
- هشدار «شکستنی — دور از نور و گرما»

### قیمت شفاف — بدون مبلغ اضافه

هیچ مبلغ اضافه‌ای در هیچ مرحله‌ای به سفارش افزوده نمی‌شود.
قیمتی که مشتری در صفحه محصول می‌بیند، همان قیمتی است که در
سبد، تسویه و فاکتور می‌بیند. تنها دو عدد می‌توانند آن را تغییر
دهند و هر دو صریح و پیش از پرداخت نمایش داده می‌شوند:
کد تخفیف (کاهنده) و هزینه ارسال.

```
جمع کالاها − تخفیف + هزینه ارسال = مبلغ پرداختی
```

### تنظیمات فروشگاه

پنل مدیریت ← تب «تنظیمات فروشگاه»: نام حقوقی، کد اقتصادی،
شناسه ملی، شماره ثبت، تلفن، نشانی و یادداشت فاکتور.

## درگاه پرداخت و پیامک

هر دو سرویس **قابل‌تعویض** هستند و با متغیر محیطی فعال می‌شوند —
بدون نیاز به تغییر کد.

| سرویس | حالت فعلی | حالت واقعی |
|---|---|---|
| پرداخت | `sandbox` (آزمایشی داخلی) | `zarinpal` |
| پیامک | `console` (کد در لاگ) | `payamito` |

```bash
# فعال‌سازی زرین‌پال
PAYMENT_GATEWAY=zarinpal
ZARINPAL_MERCHANT_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

# فعال‌سازی پیامک — سامانه فروشگاه پیامیتو است
SMS_PROVIDER=payamito
SMS_API_URL=...
SMS_API_KEY=...
SMS_SENDER=...
```

> `kavenegar` هم در کد پشتیبانی می‌شود، ولی سامانه این فروشگاه
> **پیامیتو** است. جزئیات در `docs/SMS_PAYAMITO.md`.
